# NeuroGRA 神经退行性疾病辅助鉴别诊断系统总体设计方案

**基于知识图谱与多智能体协作**

更新日期：2026 年 9 月 22 日

本项目面向神经退行性疾病相关认知障碍，研究如何在多种病因可能并存、患者资料不完整的情况下，结合多源临床资料与医学知识，完成辅助鉴别诊断并生成有依据的报告。研究以医学知识图谱与文本知识库的构建、检索和应用为主线，通过多智能体组织不同类型资料的分析，并将经医生审核的病例经验作为扩展知识来源。

## 第一部分 当前现状和背景

### 1.1 研究背景

神经退行性疾病相关认知障碍是老龄化社会面临的重要健康问题。世界卫生组织资料显示，2021 年全球约有 5700 万人患有痴呆，每年新增病例接近 1000 万。认知与日常生活能力的下降不仅影响患者，也给家庭照护和医疗服务带来长期负担。因此，及时识别认知变化、合理评估潜在病因，是开展后续诊疗与照护的重要基础。[世界卫生组织痴呆概况](https://www.who.int/news-room/fact-sheets/detail/dementia)

认知障碍的病因评估需要综合多种资料。患者可能以记忆下降为主要表现，也可能首先出现语言、行为或执行功能变化；不同病因之间存在症状重叠，同一患者还可能受到多种病因共同影响。医生需要结合病程、认知测评、日常功能、影像和检验结果，判断患者处于何种认知状态、具有何种临床表现，以及哪些病因能够解释这些发现。WHO 对痴呆类型的介绍也指出，不同类型之间的边界并不总是清晰，混合类型可以共存。[世界卫生组织痴呆概况](https://www.who.int/news-room/fact-sheets/detail/dementia)

人工智能为多源资料分析提供了技术基础，但预测出一个疾病名称与完成一份可核查的鉴别报告仍是不同任务。医生不仅需要知道系统倾向哪种病因，还需要了解该判断使用了哪些患者事实、相关医学依据是否适用，以及其他病因为何仍需考虑。实际资料又常存在检查未开展、记录不完整或不同时间结果不一致的情况，系统需要据此限定判断范围。

大语言模型能够处理临床文本和组织报告，检索增强生成能够提供外部医学依据，知识图谱能够组织疾病、表现、检查及其关系，多智能体能够分工处理不同资料。NeuroGRA 拟结合这些能力，围绕患者资料、医学知识和诊断结论之间的联系，构建面向医生的辅助鉴别诊断流程。

### 1.2 神经退行性疾病智能辅助诊断研究现状

**Xue 等实现了多模态数据支持的多病因鉴别。** Xue 等于 2024 年在 Nature Medicine 发表研究，整合人口学信息、病史、神经心理评估、功能评估与神经影像，基于 9 个队列中的 51,269 名参与者开展研究，覆盖 10 类痴呆病因，并考虑不完整输入和多病因共同贡献。这项工作表明，人工智能研究已经从特定类别识别扩展到复杂病因分析，为本项目的多病因任务提供了直接研究基础。[Xue 等，2024](https://www.nature.com/articles/s41591-024-03118-z)

**Hou 等提出 ADAgent，实现了面向 AD 分析的工具协同。** ADAgent 将大语言模型推理引擎、专用医学工具与结果协调机制结合，支持多模态或缺失输入条件下的 AD 诊断与预后任务。该方法说明，大语言模型可以作为任务组织者调用专业工具，连接不同输入和分析结果。NeuroGRA 可借鉴这种工具协同方式，同时将任务重点放在候选病因比较及其医学依据的组织上。[Hou 等，2025](https://arxiv.org/abs/2506.11150)

**Li 等提出 CARE-AD，实现了纵向病历驱动的 AD 风险评估。** CARE-AD 利用多个专业角色从长期电子病历中提取相关症状和表现，再开展领域分析与风险预测。其回顾性实验以首次记录的 AD 诊断编码为时间参照，验证了临床叙事与多角色分析用于早期风险评估的可行性。这为本项目利用病史和病程记录提供了参考，但未来风险预测与当前病例的多病因鉴别需要分别定义和评价。[Li 等，2025](https://www.nature.com/articles/s41746-025-01940-4)

**Hou 等提出 AD-CARE，实现了不完整输入下的指南支持诊断报告。** 该研究动态组织专用工具，在不补全缺失模态的条件下生成 AD 评估报告，并在六个队列的 10,303 个病例及读者研究中开展评价。它与本项目对缺失资料和报告的关注直接相关，提示本项目必须具体检验多病因比较、条件化证据与结论对应的增量，而不能将“处理缺失并生成报告”单独作为研究空白。[AD-CARE](https://arxiv.org/abs/2603.25322)
上述研究已经展示了多病因预测、工具调用和纵向信息分析的能力。本项目在此基础上进一步关注：如何把患者发现与适用医学知识对应起来，使候选比较、判断依据和资料局限能够在同一份报告中得到解释。

### 1.3 医学知识图谱与检索增强研究现状

**Wu 等提出 Medical Graph RAG，实现了医学文档与可信来源的图结构关联。** 该方法通过图结构连接用户文档和医学知识来源，并结合自上而下的检索与自下而上的回答细化，支持具有来源依据的医学回答。其研究为文本、关系和出处的联合组织提供了基础，也说明图谱可以用于组织证据，而不只是保存疾病与症状之间的联系。[Wu 等，2025](https://aclanthology.org/2025.acl-long.1381/)

**Zhao 等提出 MedRAG，实现了疾病差异知识与相似病例的联合利用。** 该方法构建四层诊断知识图谱，显式表示疾病之间的关键差异，将这些知识与检索到的相似电子病历结合，用于辅助诊断和后续问题生成。其工作直接体现了鉴别知识的价值：系统需要获取能够区分候选的内容，而不能只返回与疾病主题相近的材料。[Zhao 等，2025](https://arxiv.org/abs/2502.04413)

**Xiong 等通过 MIRAGE 基准和 MedRAG 工具包比较医学检索增强配置。** 该研究考察医学语料、检索器和语言模型的组合，为建立文本检索基线提供参考。此处 MedRAG 工具包与 Zhao 等的同名诊断图谱方法是不同工作，实验引用和实现命名应分别标明。[Benchmarking Retrieval-Augmented Generation for Medicine](https://aclanthology.org/2024.findings-acl.372/)
对 NeuroGRA 而言，这些方法提供了知识组织和联合检索的基础。本项目拟进一步围绕认知障碍鉴别任务，将医学主张与适用条件、例外及原文出处共同保存，并在检索时结合患者资料判断证据能够用于何种分析。需要验证的重点是：这样的知识组织能否提高关键鉴别依据的获取质量，并减少条件遗漏或知识误用。

### 1.4 多智能体证据整合与病例经验研究现状

**Wang 等提出 MedAgent-Pro，实现了指南规划与患者层工具执行的衔接。** 该方法通过 RAG 获取临床指南，生成疾病层面的分析计划，再利用专业工具进行患者层面的逐步分析，并检查各步骤的可靠性。它为“依据医学知识组织工具分析、以实际观察支持结论”提供了方法参考。[Wang 等，2025](https://arxiv.org/abs/2503.18968)

**Li 等提出 MedCoRAG，实现了混合证据检索与多专科迭代分析。** MedCoRAG 面向肝病病例，将 UMLS 图谱路径与临床指南共同组织为患者相关证据，再根据病例复杂程度调度专科智能体。分析中证据不足时触发定向再检索，最后由综合角色形成可追溯的诊断结论。这项工作与 NeuroGRA 的系统形态接近，可作为图文联合检索和协作流程的重要对照；本项目需围绕认知障碍的具体鉴别任务验证自身方法。[Li 等，2026](https://arxiv.org/abs/2603.05129)

**Ou 等提出 ExpRAG，实现了历史病例经验的分阶段检索。** ExpRAG 先根据电子病历定位相似患者，再提取与当前问题相关的出院报告内容，在诊断、用药及出院指导问答中评价病例经验的作用。该工作为病例经验作为补充知识来源提供了依据。NeuroGRA 拟进一步结合医生审核、病例确认状态和后续修订管理，使历史经验能够在明确来源与差异的情况下参与参考。[Ou 等，2025](https://arxiv.org/abs/2503.17933)

**Huang 等提出 SEMA-RAG，将问题解释、证据探索和答案裁决分配给不同智能体。** 检索根据证据充分性反馈继续调整，为本项目的复核机制提供直接对照；这种单次任务内的过程调整与跨病例经验库积累分别评价。[SEMA-RAG](https://arxiv.org/abs/2605.17101)

**Wang 等提出 ColaCare，将电子病历专家模型与语言模型协作结合。** 其 DoctorAgent 和 MetaAgent 组织数值预测与文本解释，为结构化资料的协作分析提供参考。原研究的电子病历预测任务与本项目病因鉴别不同，不能直接迁移效果结论。[ColaCare](https://arxiv.org/abs/2410.02551)
由这些研究可以看出，知识图谱、迭代检索和多智能体协作已经具备较充分的方法基础。本项目的研究重点是将它们用于明确的认知障碍鉴别任务，研究知识如何被组织、获取并转化为有依据的病例判断。多智能体承担资料分工与流程执行，病例经验承担补充参考，两者的实际贡献分别验证。

### 1.5 研究意义

**在方法层面，研究医学知识如何有效参与多病因鉴别。** 在已有图谱检索和疾病差异建模的基础上，本项目围绕患者发现、候选病因及知识适用条件构建检索需求，探索图关系与原文证据的联合使用。评价重点从一般文本相关性延伸到证据能否回答具体鉴别问题，以及能否正确应用于当前患者。

**在应用层面，形成便于医生核查的辅助分析结果。** 系统按病史、认知、影像和检验资料分工分析，综合比较候选病因，并将关键判断与原始记录及医学出处关联。预期能够减少分散资料整理和依据查找的负担，使医生更容易发现判断中的支持、限制和待补信息。实际效果通过病例实验和专业评阅验证。

**在经验积累层面，探索一般医学知识与审核病例的互补。** 医学指南提供一般依据，实际病例反映多项信息在同一患者中的组合及其解释。通过保存医生修正、确认状态和随访更新，系统可形成受管理的病例经验，为后续分析提供参考，并研究其是否带来额外收益。

### 1.6 研究范围

首期聚焦认知障碍场景，重点涉及阿尔茨海默病、额颞叶变性相关病因和路易体相关病因，同时将血管性贡献纳入鉴别与并存分析。血管性贡献作为相关病因因素处理，不归入神经退行性疾病类别。

输入包括病史、认知量表、检验记录、影像报告和经过验证的工具结果；原始影像处理按工具与数据条件扩展。系统输出辅助鉴别报告，由医生结合临床情况作出最终判断。当前方案处于研究设计阶段，后文所述方法及效果均需实现与验证。

## 第二部分 要解决的问题

### 2.1 多病因可能性下的辅助鉴别诊断

面对表现相近或可能共同作用的病因，如何综合患者的病史、认知、影像和检验资料，比较各候选的支持依据与限制因素，形成合理的诊断倾向和鉴别分析，是本项目首先要解决的问题。其中需要区分“现有资料尚不能区分多个病因”和“已有依据支持多个病因共同贡献”，避免将复杂病例强制归为唯一类别。

### 2.2 形成有依据、可追溯、可解释的诊断报告

如何将患者事实、医学知识与具体结论建立对应，使报告说明“为什么作出这一判断、依据来自哪里、判断能够达到什么程度”，是第二项核心问题。报告既要呈现主要结论，也要保留支持、限制和未决信息，使医生能够回到患者原始记录和医学来源核查。

资料不完整是贯穿上述两项问题的现实条件。系统应利用已有信息继续分析，同时说明缺少哪些资料及其影响；未记录不等于阴性，未开展检查也不能通过文献或相似病例补写结果。

## 第三部分 架构设计

### 3.1 总体架构

系统由患者资料与多智能体分析、共享医学知识服务、证据驱动的迭代分析、综合鉴别与报告、审核病例经验积累五部分组成。患者资料提供事实基础，知识图谱与文本库提供医学依据；各智能体围绕共享证据板开展分析，根据未解决问题查询资料或知识，再更新候选判断并形成报告。

### 3.2 患者资料与多智能体分析

患者资料进入系统后，先保留来源和时间，并整理为可共享的病例信息。分析角色按实际可用数据启动，分别提取关键发现、检索解释依据和提出待核对问题。

| 角色 | 分析内容 | 交付结果 |
|---|---|---|
| 病史智能体 | 起病方式、病程、既往史与功能变化 | 关键时间线、相关表现及信息缺口 |
| 认知智能体 | 量表结果、认知领域表现及解释背景 | 认知特征、功能影响与解释限制 |
| 影像智能体 | 影像报告或工具输出中的相关发现 | 影像特征、来源及可能的鉴别意义 |
| 检验智能体 | 检验结果、生物标志物及检测条件 | 检查发现、适用条件与待核对项 |
| 综合分析智能体 | 各类发现、医学依据与候选病因 | 候选比较、下一步查询需求及报告草案 |

智能体共享有来源的事实和分析结果。不同角色引用同一条记录时仍视为同一份证据；意见分歧通过核对依据处理，不以多数投票代替医学判断。

### 3.3 共享医学知识服务

医学知识服务包含文本知识库和知识图谱。文本库保存指南、共识及研究中的原文和上下文；图谱组织疾病、表现、检查、医学主张、适用条件及来源之间的关系。两者通过统一知识条目关联，使系统既能沿关系查找线索，也能回到原文核验。

知识服务贯穿各角色分析和综合鉴别。当某项发现需要解释时，返回相应知识及适用条件；当两个候选需要比较时，返回具有鉴别作用的依据；当结论受到质疑时，支持回溯原文和补充检索。知识更新经过来源核对和版本管理后进入系统。

### 3.4 共享证据板与迭代分析

共享证据板集中记录当前发现、候选病因、证据来源和未解决问题，并保存它们与结论的对应关系。它使不同角色围绕同一病例状态工作，也使后续查询能够回答明确的问题。

一次分析按照“分析当前证据—选择查询动作—获取结果—更新判断”的过程推进。发现医学依据不足时，检索图谱和文献；发现患者记录缺项时，查阅已有资料；遇到冲突时，核对时间、来源和适用条件。没有可获得的信息时，保留未决问题并说明其影响。

迭代在关键问题已得到处理、继续查询没有新增有效信息，或达到预设调用和时间预算时结束。轮数属于实验配置，不预先将流程固定为只能复核一次，也不允许无目标地反复查询。

### 3.5 综合鉴别与可追溯报告

综合分析先分别整理各候选的支持、削弱因素和资料局限，再形成认知状态、临床表现及候选病因层面的判断。多个病因均有依据时说明可能的共同贡献，证据不足以区分时保留鉴别不确定性。

报告包含病例概况、主要判断、鉴别分析、证据说明、缺失资料影响和后续评估方向。关键结论同时连接患者记录与医学原文，便于医生核对事实和解释。报告生成保持原有判断强度，不将“可能”改写为“确定”。

### 3.6 医生审核与病例经验积累

医生对报告进行审核和修正，符合授权及去标识化要求的病例进入经验库，保存病例特征、审核结论、相应依据和确认状态。后续随访改变判断时同步更新，并保留历史修订。

相似病例检索返回与当前患者有关的经验，同时展示相似点和重要差异。历史病例用于提示值得核对的方向，不替代当前患者事实。该模块在基本系统完成后引入，通过有无病例参考的对照评价其作用。

### 3.7 患者信息与算法交接

患者记录保留评估时点、原始值与标准化值、单位、检测方法、来源位置以及患者、照护者、医师或工具等信息提供者。状态至少区分明确存在、明确否认或阴性、未记录、未检查、不确定和记录冲突；不同访视的信息不直接覆盖。

共享证据板采用统一对象连接流程：患者观测 `Observation` 形成证据需求 `Need`；算法一返回 `EvidenceBundle`；综合分析形成 `Claim`；算法二产生 `ReviewRequest` 并更新受影响结论。每个对象保留 ID 和依赖关系，状态变化记入执行记录。

算法一向算法二交付原文证据包、适用状态、允许用途、已覆盖与未覆盖需求、来源版本及消耗预算；算法二向算法一返回目标问题、来源范围、已有事实和剩余预算。报告模块接收检查后的结论及其允许强度，不重新创造患者事实或诊断依据。

病例库同时记录授权范围、医生审核状态及诊断确认程度。审核认可、临床判断和后续证据确认分开保存；撤回授权或结论失效的记录退出对应检索范围。病例经验首先通过库更新积累，不预设模型持续训练。
## 第四部分 关键算法的设计

### 4.1 方法总体思路

方法设计围绕“知识如何形成、如何找到、如何用于判断”展开。离线阶段构建面向鉴别诊断的知识图谱与文本知识库；在线阶段采用鉴别证据检索算法，获取与患者资料和候选比较有关的依据；随后通过证据状态引导的复核算法，处理知识缺口、患者缺失和证据冲突，形成经过检查的报告结论。

知识构建为两项在线算法提供基础。算法一主要支持候选病因比较，算法二将证据核对与结论表达衔接起来；二者共同服务于第二部分的两项研究问题。具体排序参数和迭代预算由原型实验确定。

### 4.2 面向鉴别诊断的知识构建

#### 4.2.1 知识表示

知识来源以指南、诊断标准、共识及相关研究为主，围绕疾病、临床表现、检查、适用条件和鉴别关系组织。对于具有前提的医学主张，将其表示为带条件和出处的知识条款，使“主张是什么”和“何时能够使用”同时保留。

一条知识条款包含主张内容、支持或限制方向、判断层级、适用条件、例外和原文位置。例如，原文说明某项检查只有在特定方法或人群下才能用于某种判断时，图谱需要保留该前提，文本库需要保存对应的完整表述。

患者事实、通用医学知识与历史病例分别管理。患者资料说明当前观察，医学知识提供解释依据，历史病例提供个体经验，在分析时关联使用。

#### 4.2.2 构建流程

构建过程包括资料登记、结构解析、条款抽取、术语归一、关系组织、质量审核及索引发布。解析时保留章节、编号、表格和脚注，避免将医学主张与条件拆开；抽取后核对否定范围、单位、逻辑关系和原文支持。

文本库建立关键词和语义索引，图谱建立实体、条款、条件与来源之间的连接。两者使用统一条款标识和版本。无法可靠解析的内容保留原文并标记待核对，关键条款经审核后进入可使用范围。

鉴别关系需要原文比较依据，或双方可比较条款共同支持。不能因为图中没有记录某疾病的某项表现，就把它写成该疾病不存在该表现。

### 4.3 算法一 面向候选比较的鉴别证据检索

#### 4.3.1 输入与检索需求

算法输入为患者已有发现、分析角色的任务、候选病因及当前待解决问题，输出为可供分析的证据集合及其适用限制。

检索需求由病例任务形成。病史分析关注起病和演变，认知分析关注领域表现，影像和检验分析关注发现的含义及解释条件，综合分析进一步提出候选之间需要比较的问题。查询保留未知状态，避免将“未记录”写成“未出现”。

#### 4.3.2 文本与图谱联合召回

文本侧使用关键词和向量检索定位原始表述；图谱侧从疾病、表现或检查节点出发，取得相关条款、条件、例外和鉴别关系。两侧结果以条款标识对齐，形成包含主张、必要上下文与出处的证据包。

图检索补充关联信息，原文用于核验实际含义。若比较两个候选需要两侧知识，则共同保留相应条款，不能只取对初始倾向有利的一侧。相关医学知识没有找到时，返回未覆盖问题，而不是生成无来源规则。

#### 4.3.3 适用性检查与证据选择

每条知识结合患者资料标记为条件满足、不满足或未知。条件满足后，还需检查患者发现是否支持相应主张；条件不满足时说明知识不适用；条件未知时说明缺少什么信息，并交给后续复核。

在有限上下文中，证据选择综合考虑任务相关性、鉴别需求覆盖、条件完整性和内容重复。可采用预算约束下的集合选择：优先加入能够补充重要需求、且新增成本较低的完整证据包，每次选择后重新计算剩余需求与重复内容。

```text
选择目标 = 鉴别需求覆盖 + 任务相关性 − 重复内容
约束条件 = 证据包完整、用途正确、总长度不超过预算
```

其中，完整证据包保留必要条件和出处，不能通过删除关键前提使其满足长度限制。相关性分数仅用于选择材料，不作为患病概率。后续复核取得新证据时，对新旧材料重新选择，保持最终上下文预算一致。

#### 4.3.4 预期作用

该算法拟使检索从疾病一般介绍转向当前病例的具体鉴别需求，减少重复背景材料，并使条件、限制与支持依据一同进入分析。其价值通过同知识、同预算下的混合文本检索、普通图检索及不同选择策略对照验证。

### 4.4 算法二 证据状态引导的迭代复核

#### 4.4.1 建立结论与证据的对应关系

算法接收患者事实、算法一返回的证据和初步结论，为每项结论记录支持依据、限制因素和未解决问题。检查的重点是：患者事实是否存在、知识是否适用、引用是否支持当前表述，以及结论是否超出了依据允许的层次。

证据冲突先核对主体、时间、方法和判断层级。不同时间的结果可能反映变化，不同层级的信息可能同时成立；多个候选都有支持也不直接构成矛盾。

#### 4.4.2 根据问题类型决定复核动作

| 证据状态 | 对应动作 | 更新依据 |
|---|---|---|
| 缺少相关医学知识 | 定向检索图谱与原文 | 新条款是否回答当前问题 |
| 条款条件或例外不完整 | 补查原文上下文 | 条件含义是否得到核实 |
| 患者必要信息未知 | 查阅已有病历、报告或工具记录 | 是否取得真实患者信息 |
| 资料或解释存在冲突 | 核对原始记录及适用范围 | 是否有依据说明差异 |
| 引用不支持结论 | 更换依据、缩小表述或撤回结论 | 修改后是否与来源一致 |

每次复核明确目标和成功条件。例如，某知识条款要求已知检测方法，而患者报告未标明方法，系统应查阅原报告；若仍无该信息，则继续保留未知。介绍该方法的文献不能证明患者采用了该方法。

#### 4.4.3 更新判断与停止

复核结果返回后，更新相关事实、证据和结论。需要补知识时调用算法一，取得真实患者信息时重新检查条件，对已被否定的依据撤回相应推断。重复检索到同一内容不增加证据强度。

迭代优先解决影响主要结论的问题，并受总调用数、时间和上下文预算约束。关键问题已处理、没有可执行动作、没有新增有效信息或预算耗尽时停止。仍存在缺口或冲突的结论保留限制，已经有充分依据的其他判断继续保留。

#### 4.4.4 形成可追溯报告

报告中的关键判断建立两条关联：

```text
具体结论 → 患者发现 → 病历、量表、影像报告或检验原始位置
具体结论 → 适用医学条款 → 指南、共识或研究原文位置
```

报告据此说明当前判断、其他候选及资料缺失影响。医学知识没有支持某一判断，不自动意味着该判断已被排除；必要前提未知时，也不能写成已确认。证据链用于帮助医生核查依据，其正确性仍需独立评价。

### 4.5 方法验证与实施安排

验证围绕两项研究问题展开。一方面评价候选识别、病因比较与共同贡献分析；另一方面评价患者事实准确性、引用支持、关键依据覆盖和缺失说明。诊断评价与报告依据评价分别报告，避免用文字质量替代诊断表现。

首先比较文本检索与图文联合检索，检验知识组织和鉴别证据获取的作用；随后比较有无证据状态复核，检验结论错误与有效内容覆盖的变化；再在相同模型、知识和调用预算下比较单智能体与多智能体；最后考察经审核病例参考的增量价值。

数据按患者划分，测试病例及诊断时点之后的信息不进入待诊断输入或经验库。数据仅具有有限标签时，只评价其能够支持的任务；混合病因评价需要相应标注。缺失资料实验同时关注错误推断是否减少，以及已有资料支持的有效判断是否得到保留。

实施依次完成小范围医学知识建设、鉴别证据检索、迭代复核与报告、多智能体集成及病例经验扩展。预期形成知识图谱与文本知识库、关键算法原型和辅助鉴别诊断系统，并通过对照实验与专业评阅确定各部分的实际贡献。

### 4.6 资料准备与评价样本

资料建设分为医学知识、术语资源和病例评价数据三条线。指南、共识及检查规范优先用于知识构建，综述与原始研究作为补充；方法论文仅作技术参考，不因保存在 `paper/` 中就进入医学证据库。来源登记包括标题、用途、机构、日期、版本、原文位置、许可、适用人群和审核状态。

首批知识覆盖 AD、DLB、bvFTD、PPA 与血管性认知损害的核心标准，以及相关中文指南、量表解释、影像和检验条件。优先整理 AD—DLB、AD—FTLD、AD—血管性及 DLB—FTLD 四组鉴别知识；在线仍保留既定四组病因之间全部六个候选对的检查入口，知识缺口显式记录。药物与安全知识只在解释混杂因素或已有证据时纳入，完整治疗推荐属于后续范围。

术语从本地疾病、综合征、表现、检查和生物标志物词表起步，保留中英文名称与别名。HPO、Mondo、UMLS、MeSH、ICD、SNOMED CT 及基因、药物资源作为按需核验的扩展，不以名称相同认定概念等价，不把全量本体导入设为首期前提。

病例来源按任务匹配程度选择：NACC 作为多病因与纵向评估的候选来源，ADNI 用于 AD 及多模态任务，OASIS 用于相应影像和临床资料验证，本地病例用于中文应用场景；NINDS CDE 用于字段设计，不作为患者队列。最终以实际获准数据的字段、标签和完整性为准，访问条件在申请时核对。

除病例标签外，还需要独立的算法标注。检索样本标注目标需求、完整条款、条件例外、允许用途、重复关系和精确出处；复核样本标注缺口类型、可获得记录、正确动作、成功判据及合理结论强度。开发和测试按患者、文档或条款组隔离，自然缺失与人为删除资料的结果分开报告。

规模分阶段安排：工程试点先处理 1 份中文共识，再扩展到 3～5 份中英文文档，初步标注约 50～100 条条款和 20 个检索问题；研究阶段再依据审核资源扩充。既有算法文档中的 20～40 份资料、500～1500 条条款及 100～300 个证据包属于规模规划，不是试点验收门槛或已完成数据。完整的来源候选清单和字段要求保存在第 4.11 节附录 A。

### 4.7 PDF 知识构建的首期工程方案

首期交付独立的离线知识构建流水线和知识查询服务，从显式选择的 PDF 生成可核查底稿、文本索引和条件化图谱。该模块暂不处理患者诊断、多智能体调度或复杂患者条件求值；其结果通过统一接口提供给后续算法。

**解析与切分。** 保存不可变 PDF 快照、文件哈希、物理页码、印刷页码、阅读顺序及页面坐标。原始解析文本与清洗文本分开，OCR 内容标明转录方式。采用父子块组织：子块用于检索，父块补齐完整条款、表头、脚注和上下文；300～600 tokens 仅作切分起点，不能破坏语义条件。

**抽取与审核。** 模型按固定 schema 生成候选知识，校验原文区间、数值单位、关系类型和逻辑结构。条款采用不可变修订记录，修改后重新校验。首期正式图谱仅发布人工通过的医学条款；文本批准与条款批准分开，允许有效正文进入文本检索，但不据此自动生成可执行规则。不能解析的条件保存为 `TEXT`，不自动执行。

**存储与发布。** SQLite 保存权威状态和关联，JSONL 与 PDF 快照支持审计和重建；BM25、Qdrant 和 Neo4j 为派生索引。候选发布版本通过图、文本和来源一致性检查后，统一切换活动版本。一次查询只解析一次版本指针，发布中途失败时旧版本继续服务。

**增量与恢复。** 首版按变更文档重建，章节级差分作为后续优化。缓存键包含输入、阶段实现、模型、提示词、术语及相关配置版本；只变更嵌入模型时只重建向量和发布版本。失败任务有状态和错误记录，可断点恢复；重复导入同一文件不重复入库。

| 组成 | 首期候选技术 | 实施要求 |
|---|---|---|
| 程序与结构模型 | Python 3.11+、Pydantic | 领域对象不依赖具体模型或数据库厂商 |
| 文档解析 | Docling 适配器及按需 OCR | 用中文、英文、双栏、表格和扫描样本验证 |
| 权威记录 | SQLite、JSONL、源 PDF 快照 | 事务、版本及来源关系可核查 |
| 文本检索 | BM25、Qdrant、RRF 融合 | 记录分词、嵌入、参数和索引版本 |
| 图谱检索 | Neo4j | 按发布版本隔离，条款条件和出处完整 |
| 模型服务 | 抽取与嵌入分别适配 | 根据可用资源选型，样本评价后锁定版本 |
| 使用入口 | CLI 和 Python 查询接口 | 首期不开发完整网页界面 |

以上为既有工程方案的候选路线，不表示依赖已安装或性能已验证。完整的模块目录、数据字段、接口、配置及 S01～S12 执行步骤保存在第 4.12 节附录 B。

### 4.8 评价指标与工程验收

| 环节 | 评价内容 | 对照或验收方式 |
|---|---|---|
| 知识构建 | 实体关系准确性、条件结构、否定与单位保留、引用位置、审核耗时 | 条款切分与定长切分、条件表示与普通三元组对照 |
| 鉴别证据检索 | 固定预算下完整需求覆盖、条件误用、召回上限、重复内容 | 同候选池 Top-k/MMR；信息等量的平铺条款与图关系对照 |
| 证据复核 | 错误强结论、患者缺失误补、真实解决率、可兼容证据误报冲突 | 不复核、固定查询和一般缺口反馈；相同累计预算 |
| 报告与系统 | 引用支持、关键事实遗漏、有效回答覆盖、候选识别及病因判断 | 独立病例标签、专业评阅、单多智能体及病例库消融 |

检索核心指标 `DEC@B` 为预算 B 内完整、正确覆盖的人工金标准需求数除以该问题的金标准需求总数；无适用需求的样本单列。引用“能定位”和“支持结论”分别测量；保留未决不计为复核成功。错误指标与回答覆盖同时报告，不以系统自己的评分代替独立标注。

工程验收要求：已发布条款的来源外键及原文区间检查全部通过，定位正确性再独立人工抽查；未审核条款不能进入正式图谱；重复导入保持幂等；图、文本和引文版本一致；失败页和失败任务均有记录；发布失败不影响旧版本；可按清单重建或回滚。语义准确率、检索召回与耗时目标在首批基线测量后确定。

单路检索服务故障时，只能按配置降级并明确标记；来源或版本完整性失败时不返回看似完整的图谱证据。累计调用、token、时间和费用均记录，无法取得的统计标为未知，不记为零。

### 4.9 分阶段交付与论文组织

| 阶段 | 交付 | 完成依据 |
|---|---|---|
| 1. 结构化底稿 | 登记、PDF 快照、页面块、原文位置与父子块 | 试点文档来源与上下文可回查 |
| 2. 审核知识底座 | 文本检索、候选条款、实体归一、条件树及审核 | 文本和图谱能同版发布并查询 |
| 3. 两项算法 | 鉴别证据选择、状态复核及结论约束 | 独立标注集、基线与失败案例分析 |
| 4. 系统集成 | 资料分工、共享证据、分层报告与医生审核 | 同模型和资源条件下的系统评价 |

#### 1. 先明确需要建立的三套数据

NeuroGRA 不应把所有资料直接放入同一个向量库。至少要区分以下三类数据。

| 数据集合 | 主要内容 | 系统用途 | 是否进入 RAG | 是否进入知识图谱 |
|---|---|---|---|---|
| 医学知识语料库 | 指南、诊断标准、共识、系统综述、检查规范、药品说明等 | 为回答和复核提供可引用的医学依据 | 是 | 抽取其中经过审核的关系和条款 |
| 术语与结构化知识库 | 疾病、症状、检查、基因、药物等标准术语及关系 | 实体规范化、图检索、关系扩展 | 只将定义或说明作为辅助文本 | 是 |
| 病例与评价数据集 | 脱敏病历、量表、检验、影像报告、最终诊断及随访 | 构造查询、训练或评价系统 | 原则上不进入公共知识库 | 患者子图须隔离，不能并入通用医学事实图谱 |

核心原则是：**医学知识回答“通常什么条件支持某结论”，患者资料回答“当前病例实际观察到了什么”**。二者必须使用不同标识、权限和更新时间，并在推理阶段临时关联。

#### 2. 第一优先级：诊断标准、临床指南和专家共识

这类资料是 RAG 主库和“条件化鉴别证据图”的核心。采集时不能只保存结论句，还要保存前提、必要条件、排除条件、证据等级、适用人群、检查方法及版本。

##### 2.1 阿尔茨海默病与认知障碍分层

建议收集：

1. AD 的生物学定义、诊断和分期标准；
2. 主观认知下降、轻度认知障碍和痴呆的临床界定；
3. 典型与非典型 AD 临床表型，如遗忘型、后部皮质萎缩和语言型表现；
4. 淀粉样蛋白、tau 和神经退行性标志物的解释条件；
5. 脑脊液、PET、血液标志物的检测平台、阈值来源和适用场景；
6. AD 与 DLB、FTLD、血管性认知损害、抑郁、谵妄及可逆病因的鉴别条款。

首要来源可采用 Alzheimer’s Association 的 [2024 年 AD 诊断与分期标准入口](https://www.alz.org/research/for_researchers/diagnostic-criteria-guidelines)。该标准强调 AD 的生物学定义，并将生物学诊断与临床表现分开，因此图谱中也应分别建立“疾病生物学状态”和“临床综合征状态”。该页面同时说明该标准不等同于临床实践指南，不能把研究框架无条件改写为临床规则。

##### 2.2 路易体相关疾病

建议收集：

- DLB 核心临床特征、支持性特征和指示性生物标志物；
- 认知波动、视幻觉、快速眼动睡眠行为障碍和帕金森综合征的定义与时间关系；
- 多巴胺转运体成像、MIBG 心肌显像、多导睡眠监测等检查的解释条件；
- DLB 与帕金森病痴呆的时间界定；
- DLB 与 AD、血管性认知损害及药物相关症状的鉴别；
- 抗精神病药敏感性等安全相关知识。

首要来源为 DLB Consortium 的 [第四次共识报告](https://pmc.ncbi.nlm.nih.gov/articles/PMC5496518/)。该报告明确区分临床特征和诊断性生物标志物，适合转换为“条款—条件—证据类型—诊断级别”的图结构。

##### 2.3 额颞叶变性相关综合征

至少覆盖：

- 行为变异型额颞叶痴呆（bvFTD）的可能、很可能和病理确诊层级；
- 原发性进行性失语（PPA）及语义型、非流利/语法障碍型、词汇减少型三个变体；
- FTLD 与运动神经元病、进行性核上性麻痹、皮质基底节综合征的交叉表现；
- MAPT、GRN、C9orf72 等常见遗传因素及家族史；
- 影像支持模式与临床表型之间的关系；
- bvFTD 与精神障碍、AD、DLB 的鉴别条件。

可从 [bvFTD 国际共识标准原文](https://www.ftdtalk.org/wp-content/uploads/2020/02/RascovskyBrain2011.pdf) 和 [PPA 分类共识](https://pmc.ncbi.nlm.nih.gov/articles/PMC3059138/) 建立首批条款。PPA 共识将临床分类、影像支持和明确病理分层，图谱中不应把这三个层级合并为一个“确诊”关系。

##### 2.4 血管性认知损害及混合病因

建议收集：

- 轻度和重度血管性认知障碍的定义；
- 卒中与认知下降的时间联系；
- 执行功能、加工速度及注意功能特征；
- 大血管梗死、腔隙、白质高信号、微出血和战略部位病灶的影像条件；
- 血管危险因素与已经形成的脑血管损害之间的区别；
- AD 与血管病理共存时的表述规则。

基础材料可采用 [VASCOG 2014 标准](https://pmc.ncbi.nlm.nih.gov/articles/PMC4139434/)；后续应补充并核对 2025 年发表的 [VasCog-2-WSO 修订标准](https://jamanetwork.com/journals/jamaneurology/fullarticle/2839119)。由于项目将血管性贡献作为鉴别和共存因素，图谱关系宜使用“支持血管性贡献”“与认知下降存在时间关系”等精确表述，避免简单写成“属于神经退行性疾病”。

##### 2.5 中国临床环境资料

国际标准之外，还应收集以下中文权威材料：

- 中华医学会、中华医学会神经病学分会及相关学组发布的认知障碍、AD、DLB、FTD 和血管性认知障碍指南或共识；
- 国家卫生健康委员会发布的诊疗指南、临床路径、检查规范；
- 中国药品说明书、国家药监局安全性公告；
- 国内生物标志物、神经心理量表和影像规范的专家共识；
- 中国人群中的量表常模、教育程度校正和本地语言版本。

中文期刊全文通常受版权约束。获得机构订阅并不等于可以批量复制到可分发语料库。应逐篇记录授权状态；无法取得全文再利用许可时，仅保存题录、摘要、人工整理的结构化条款及合法引用片段。

#### 3. 第二优先级：检查、量表和临床表现资料

##### 3.1 病史与临床表现

应覆盖发病方式、进展速度、首发症状、认知域、精神行为、运动、睡眠、自主神经、日常生活能力和照护者观察。每项表现至少保留下列属性：

- 标准名称、同义词和否定表达；
- 起始时间、持续时间、频率和严重度；
- 信息来源是患者、照护者、医师观察还是设备；
- 对哪些病因具有支持、反对或仅提示作用；
- 只有在何种组合、时相或阈值下才可使用；
- 可能的药物、精神、代谢或急性疾病混杂因素。

##### 3.2 神经心理和功能量表

建议建立“量表目录”，而不是默认把量表题目全文都放入 RAG：

| 领域 | 候选工具 | 需要记录的元数据 |
|---|---|---|
| 全局认知 | MMSE、MoCA | 版本、语言、教育校正、阈值来源、版权 |
| 痴呆分期 | CDR、CDR-SB | 访谈对象、评分规则、培训要求 |
| 日常功能 | ADL、IADL、FAQ | 适用人群、评分方向、照护者信息 |
| 行为精神症状 | NPI 等 | 频率、严重度、照护者负担 |
| 额叶行为 | FAB、FrSBe、CBI-R 等 | 语言版本、常模及授权 |
| DLB 相关 | 认知波动、RBD、帕金森症状工具 | 诊断级别、筛查与确诊差别 |
| 抑郁和谵妄 | GDS、CAM 等 | 用于鉴别或共病，不等同于病因结论 |

量表可能具有版权、培训或商业授权限制。NINDS 的通用 CDE 页面也明确指出，专有量表不会因被推荐而自动开放。因此需要分别保存“量表名称和解释知识”“获授权的题项/评分规则”和“患者分数”，禁止从网页任意复制量表全文。[NINDS 通用 CDE](https://commondataelements.ninds.nih.gov/General%20%28For%20all%20diseases%29)

##### 3.3 实验室与生物标志物

资料范围包括：

- 排除可逆或共存因素的基础检验，如血常规、电解质、肝肾功能、甲状腺功能、维生素 B12/叶酸及感染相关检查；
- CSF Aβ42、Aβ42/40、总 tau、p-tau 等；
- 血浆 Aβ、p-tau 亚型、NfL、GFAP 等研究进展；
- APOE 及 FTLD 相关基因；
- 检验前处理、检测平台、样本类型、单位、参考范围和阈值来源。

图谱中不能建立脱离平台的固定阈值。例如“p-tau181 升高”必须关联样本类型、检测平台、实验室参考范围、研究或指南来源和版本。新兴血液标志物应标记为“研究证据”“临床可用”或“指南推荐”等不同成熟度。

##### 3.4 神经影像与其他检查

建议收集：

- MRI/CT 的萎缩部位、血管性病灶、脑积水、肿瘤及其他排除性表现；
- FDG-PET、淀粉样蛋白 PET、tau PET 的典型模式和解释边界；
- DAT-SPECT、MIBG 和 PSG 在 DLB 判断中的用途；
- EEG 等检查在快速进展性认知障碍或其他鉴别中的用途；
- 每类检查的采集规范、报告词汇、质量控制和假阳性/假阴性条件。

首期系统输入如果只是影像报告，就只构建“报告发现”节点，不能将其表述为系统直接识别了原始影像。未来接入影像模型时，再增加模型版本、输入序列、质量控制和置信度字段。

#### 4. 第三优先级：治疗、安全性和随访资料

即便论文重点是鉴别诊断，也建议保留有限的治疗和安全知识，因为药物既可能影响症状，也可能构成重要禁忌或混杂因素。应收集：

- 已获批药物的适应证、禁忌证、警示、不良反应和监测要求；
- 对症治疗与疾病修饰治疗的证据层级；
- 药物导致认知下降、谵妄、帕金森症状或睡眠异常的可能性；
- 非药物干预和照护建议；
- 复诊、量表变化、功能变化和生物标志物随访建议。

首期图谱只需支持“药物可能导致某表现”“某疾病对某类药物具有安全风险”“某治疗适用于满足特定条件的人群”等关系，不需要扩展成完整临床决策支持系统。

#### 5. 术语本体和外部结构化知识

##### 5.1 推荐的基础术语源

| 资源 | 建议用途 | 注意事项 |
|---|---|---|
| ICD-10/ICD-11 | 疾病分类、统计编码 | 分类码不能代替细粒度临床知识；核对本地使用版本和授权 |
| SNOMED CT | 临床概念、观察与关系 | 中国地区许可及发行版本需单独确认 |
| UMLS | 多术语映射、CUI 和语义类型 | 需 UTS 账户；组成词表各有许可限制 |
| MeSH | 文献检索词和层级扩展 | 适合查询扩展，不足以单独承担临床图谱 |
| HPO | 症状/表型标准化 | 免费使用但应保留版本、署名且不得擅改原始逻辑关系，[许可说明](https://human-phenotype-ontology.github.io/license.html) |
| Mondo | 疾病统一标识和跨本体映射 | CC BY 4.0，可下载 OWL/OBO/JSON，[下载说明](https://mondo.monarchinitiative.org/pages/download/) |
| HGNC、NCBI Gene、ClinVar | 基因及临床变异 | 区分基因—疾病关联与具体变异致病性 |

| RxNorm | 药物名称规范化 | 内容偏美国市场；完整版本和组成词表存在许可约束，[NLM 说明](https://www.nlm.nih.gov/research/umls/rxnorm/docs/termsofservice.html) |
| Open Targets | 靶点—疾病证据 | 更适合机制与科研扩展；开放下载和 API 见[官方文档](https://platform-docs.opentargets.org/data-access) |

建议选用 Mondo 或项目自建疾病 ID 作为疾病主键，HPO 作为表型主键，再保存 ICD、SNOMED CT、UMLS、MeSH 的交叉映射。不能把不同术语库中名称相同的概念自动视为完全等价，所有自动映射都要保留映射类型和置信度。

##### 5.2 首期知识图谱实体

首期实体类型建议控制在以下范围：

1. `Disease`：病理性疾病或病因；
2. `Syndrome`：MCI、痴呆、PPA 等临床综合征；
3. `Phenotype`：认知、行为、运动、睡眠和自主神经表现；
4. `Finding`：检验或影像发现；
5. `Test`：量表、实验室检测、影像或生理检查；
6. `Biomarker`：分子、遗传、影像或病理标志物；
7. `Gene` 与 `Variant`；
8. `Drug` 与 `Intervention`；
9. `RiskFactor` 与 `Comorbidity`；
10. `CriterionSet`、`Clause`、`Condition` 和 `Exception`；
11. `SourceDocument`、`SourceSpan`、`Organization` 和 `Version`。

##### 5.3 首期核心关系

```text
Disease --has_phenotype--> Phenotype
Disease --has_biomarker--> Biomarker
Disease --associated_with_gene--> Gene
Syndrome --may_be_caused_by--> Disease
Finding --supports_under_condition--> Disease
Finding --argues_against_under_condition--> Disease
Finding --differentiates--> DiseasePair
Test --measures--> Biomarker_or_Phenotype
Test --requires_method--> Method
Clause --requires--> Condition
Clause --has_exception--> Exception
Clause --supports_level--> DiagnosticLevel
Clause --derived_from--> SourceSpan
SourceSpan --part_of--> SourceDocument
SourceDocument --issued_by--> Organization
SourceDocument --supersedes--> SourceDocument
Drug --may_cause--> Phenotype
Drug --has_safety_issue_in--> Disease_or_Condition
```

“supports”关系不能只连接两个节点。它至少还应携带适用条件、证据方向、诊断层级、来源定位、发布日期、审核状态和置信度，否则无法支持论文提出的条件感知检索。

#### 6. 文献资料的范围与采集方式

##### 6.1 应收集的文献类型

按优先顺序建议为：

1. 国际或国家级诊断标准和临床指南；
2. 专业学会专家共识及检查规范；
3. 系统综述和高质量循证综述；
4. 关键生物标志物、鉴别诊断和纵向队列研究；
5. 病理—临床对应研究；
6. 典型病例系列，仅用于发现少见表现和关系候选；
7. 教材、患者教育网页和百科，用于术语解释，不作为高等级诊断依据。

##### 6.2 文献入库范围

PubMed 题录、关键词和摘要可用于检索索引及筛选；全文语料优先使用 PMC Open Access 子集或明确取得许可的文献。PMC 明确要求自动化获取使用其官方 API，并且并非所有 PMC 文章都允许文本挖掘或再分发，因此要逐篇保存许可信息。[PMC 开发者说明](https://pmc.ncbi.nlm.nih.gov/tools/developers/)

每篇文档至少保存以下元数据：

```text
document_id, title, authors, organization, document_type,
publication_date, effective_date, version, language,
doi_or_url, license, acquisition_method, supersedes,
population, disease_scope, evidence_level, reviewer,
review_status, checksum, indexed_at
```

每个切片应额外保存章节标题、页码或段落号、字符范围、表格/图编号、上级条款、引用链和原文哈希。不要按固定字符数把诊断条款及其条件拆开。

#### 7. 病例和评价数据集

病例数据主要用于系统评测，不应作为可引用医学知识。对于本课题，优先级最高的不是海量原始 MRI，而是具有**多病因、纵向随访、结构化临床评估和最终诊断**的数据。

| 数据源 | 可用内容 | 对本项目的价值 | 约束或风险 |
|---|---|---|---|
| NACC | 纵向临床评估、神经心理、诊断、病理、影像及生物标志物；另有 FTLD 和 LBD 模块 | 与 AD、FTLD、LBD 多病因范围最匹配，可建立鉴别和随访任务 | 需按流程申请；不同中心的数据完整性和采集频率不同。参见 [NACC Researcher’s Guide](https://www.naccdata.org/the-nacc-researchers-guide) |
| ADNI | 临床、认知、MRI/PET、生物体液、遗传和病理等纵向数据 | 适合 AD 连续谱和多模态一致性验证 | 需申请并遵守数据使用和发表政策，[ADNI 数据页](https://adni.loni.usc.edu/data-samples/adni-data/) |
| OASIS | 多批次 MRI、临床及认知资料 | 可用于影像相关扩展与公开基线 | 数据集之间范围不同；受数据使用协议和当前地域访问政策限制，[访问条款](https://sites.wustl.edu/oasisbrains/home/access/) |
| NINDS CDE/PDBP | 通用神经病学数据元素、帕金森病数据字典和表单 | 用于设计统一字段、允许值和 CRF，不应当作病例队列 | 某些量表仍有独立版权。[NINDS CDE](https://www.ninds.nih.gov/current-research/scientific-resources/ninds-common-data-elements) |
| 本地医院回顾性病例 | 中文病史、报告、检验、实际缺失模式和鉴别过程 | 最符合最终应用环境 | 必须通过伦理审批、脱敏、访问控制和数据使用协议 |
| 专家编写或公开病例 | 可控制缺失、冲突和罕见鉴别条件 | 适合构造挑战集和错误分析 | 必须标记为合成/教学病例，不能与真实病例性能混报 |

NACC 的资料结构尤其适合本项目，因为其公开说明中包含 UDS、FTLD 模块和 LBD 模块，并明确区分病因诊断与认知状态。ADNI 更适合 AD 生物标志物和纵向变化，但不足以单独评价 FTLD、DLB 与血管性贡献之间的全面鉴别。

##### 7.1 每个病例至少需要的字段

- 基本人口学信息及教育程度；
- 主诉、发病年龄、病程、进展模式；
- 患者和知情者提供的病史；
- 各认知域和神经精神表现；
- 日常生活能力；
- 神经系统查体、运动、睡眠和自主神经表现；
- 量表原始分、总分、版本、语言和日期；
- 实验室数据的数值、单位、参考范围、方法和日期；
- 影像报告、检查日期和必要时的结构化标签；
- 用药、共病及潜在混杂因素；
- 每次随访时的综合征状态、候选病因及确定程度；
- 最终诊断依据、病理或遗传证据；
- 缺失原因，而不是把缺失字段记成阴性。

#### 8. 针对两项关键算法必须额外标注的资料

##### 8.1 条件感知的鉴别证据检索

为评价“是否找到了真正能区分候选病因的证据”，需要人工建立一个小而可靠的鉴别证据金标准。每个候选疾病对应至少标注：

- 鉴别需求；
- 应检索到的条款；
- 条款适用条件和例外；
- 支持、反对、限制解释或仅提示补检查的用途；
- 来源和精确定位；
- 哪些证据内容重复，哪些虽然同源但属于不同必要条款；
- 在限定 token 预算下不可缺少的证据包。

例如 AD 与 DLB 的鉴别不能只标注“视幻觉—DLB”，还需要标注出现时间、反复性、是否成形、药物或谵妄等替代解释，以及它在对应标准中的诊断地位。

##### 8.2 证据状态引导的有界复核

需要构建含下列情形的病例或问题集：

- 医学知识没有检索到，但患者资料已经存在；
- 医学条款存在，但患者未做相关检查；
- 患者已做检查，但方法、单位或日期缺失；
- 两条证据表面冲突，实际上人群、方法或时点不同；
- 支持和反对证据均存在，复核后仍不能消除；
- 引用过期、被新标准替代或无法定位；
- 复核不能解决问题，系统应保留多候选或降低结论强度。

每条样本应标注正确动作：重新检索医学知识、补取已有患者资料、提示未来采集、重新比较证据、调整结论或保持不确定。这样才能评价“是否采取了正确复核动作”，而非只评价最后诊断是否碰巧正确。

#### 9. 资料质量、版本与授权管理

##### 9.1 来源等级

建议采用以下内部等级，但不要把等级直接解释为某个患者结论的概率：

```text
A：正式诊断标准、循证临床指南、监管机构文件
B：专业学会共识、系统综述、标准化检查规范
C：高质量原始研究、纵向队列、病理验证研究
D：病例系列、叙述性综述、教材
E：患者教育材料、普通网页和未经审查内容
```

A 级来源也可能不适用于当前患者；C 级研究也可能提供某一新生物标志物的重要证据。因此最终排序应同时考虑来源等级、条款适用性、发表时间和任务相关性。

##### 9.2 每条知识的审核状态

```text
machine_extracted → terminology_aligned → human_reviewed
→ clinically_reviewed → active / superseded / rejected
```

自动抽取内容在完成临床审核前不能作为高确定性诊断规则。新版本发布后，应将旧条款标记为 `superseded`，保留历史关联，不能直接覆盖或删除。

##### 9.3 版权、伦理和隐私

- 文献全文、量表、药物数据库和术语库分别核对许可；
- 保存来源许可、版本日期和访问方式；
- 真实患者资料必须经伦理审批和充分脱敏；
- 通用医学图谱与患者子图物理或逻辑隔离；
- 不把受限数据上传到未经批准的外部模型服务；
- 对训练、调参和测试病例按患者划分，避免同一患者不同访视跨集合泄漏；
- 发布模型或知识库时，不随包分发授权不允许再发布的原文或量表题项。

#### 10. 推荐的首期最小资料包

为了使硕士论文范围可完成，不建议一开始建设覆盖全部神经退行性疾病的大图谱。可先完成以下最小集合：

##### P0：必须完成

1. AD、DLB、bvFTD、PPA 和血管性认知损害的核心诊断标准；
2. 每类疾病 1 至 2 份高质量中文指南或共识；
3. 认知状态、核心临床表现、常用检查和生物标志物术语表；
4. AD—DLB、AD—FTLD、AD—血管性、DLB—FTLD 四组重点鉴别关系；
5. 每个诊断条款的条件、例外、来源定位及版本；
6. 经过专家审核的 100 至 300 个鉴别证据包；
7. 一组专门包含缺失、冲突和过期引用的复核评价样本；
8. 一套独立病例测试集，病例内容不进入 RAG 知识库。

##### P1：论文实验稳定后扩展

- 更多中文真实世界资料和本地常模；
- 血液生物标志物平台差异；
- FTLD 遗传与病理关系；
- 药物安全性及可逆性认知障碍；
- 纵向状态变化和混合病理。

##### P2：后续研究

- 原始 MRI/PET 模型输出；
- 蛋白、通路和多组学机制图谱；
- 全神经退行性疾病范围；
- 治疗推荐和疗效预测。

#### 11. 建议的实际收集顺序

1. 固定疾病范围和诊断层级，先编制来源清单；
2. 下载或登记五类核心诊断标准，记录版本与许可；
3. 建立疾病、综合征、表型、检查和生物标志物词表；
4. 以四组重点鉴别对为单位人工整理条款；
5. 将条款连同条件、例外和原文定位写入结构化表；
6. 经医学人员审核后生成图谱边和 RAG 证据包；
7. 再补充综述与原始研究，不让低等级来源覆盖正式标准；
8. 单独准备病例评价集及缺失/冲突挑战集；
9. 冻结知识库版本，记录实验所用文档、图谱和病例版本；
10. 论文实验完成后再扩充病种和机制层知识。

按照这一顺序，最先得到的不是一个规模很大但关系含混的医学图谱，而是一套能够支撑“条件完整检索”和“证据状态复核”的小型高质量知识底座，这与 NeuroGRA 两项核心算法的验证目标直接对应。

#### 3. 核心数据结构

##### 3.1 ID、修订与公共字段

| 字段 | 生成规则 |
|---|---|
| `document_id` | `doc_` + PDF 字节 SHA-256；同字节同 ID |
| `parse_id` | 文档 ID + 解析器版本 + 解析配置指纹的哈希 |
| `block_id` | parse_id + 页码 + 页面阅读序号的哈希 |
| `span_id` | parse_id + 原文定位列表 + 切分版本的哈希 |
| `chunk_id` | span ID 列表 + 清洗/切分配置 + 块角色的哈希 |
| `entity_id` | 已确认规范概念使用持久 UUID；后续更名不改变 ID |
| `candidate_id` | 抽取任务缓存键 + 候选序号的哈希 |
| `clause_id` | 候选首次入库分配持久 UUID，修订不改变 |
| `revision_id` | 条款 ID + 修订序号；修订内容不可变 |
| `release_id` | 一次发布的 UUID，关联不可变 manifest |

内容哈希采用规范化 JSON：排序键、固定编码、禁止 NaN，集合字段排序而有序逻辑列表保留顺序。不同解析版本不强行复用原文片段 ID。跨来源相似主张通过 `claim_group_id` 分组，不合并来源记录。

公共字段包括 `schema_version: str`、`created_at: datetime`。可修订对象通过追加 revision 更新，不原地覆盖已发布内容。

##### 3.2 Document 与 ParsedBlock

`Document`：

| 字段 | 类型 | 说明 |
|---|---|---|
| document_id / checksum | str | 文件标识和完整哈希 |
| source_path / snapshot_path | str | 导入位置与不可变副本位置 |
| title | str \| null | 已核验或待确认标题 |
| source_role | Literal | clinical_guideline / clinical_research / method_reference |
| language | str \| null | zh / en 等 |
| publication_date / source_version / doi / organization | str \| null | 来源元数据 |
| metadata_status | Literal | pending / verified |
| source_family_id / supersedes_document_id | str \| null | 人工确认的版本关联 |
| page_count | int \| null | 成功解析后写入 |

`ParsedBlock`：`block_id, parse_id, document_id, page_no, printed_page_label?, reading_order, block_type, raw_text, bbox, page_width, page_height, extraction_method, parser_quality?, table?, issues[]`。

- `block_type`：heading / paragraph / list_item / table / caption / footnote / figure。
- `bbox`：左上角原点、归一化到 `[0,1]` 的 `[x0,y0,x1,y1]`；适配器负责转换 PDF 坐标。
- `extraction_method`：native_text / ocr / manual_transcription。
- `table` 包含行列数及单元格列表，每格保存 `row, col, row_span, col_span, text, bbox, is_header`；跨页表通过 `table_group_id` 连接。
- 无可靠解析质量分数时 `parser_quality=null`，不得构造虚假概率。

##### 3.3 SourceSpan 与来源定位

```python
class SourceLocator(BaseModel):
    block_id: str
    start: int                 # 对应 ParsedBlock.raw_text
    end: int

class EvidenceRef(BaseModel):
    span_id: str
    start: int                 # 对应 SourceSpan.original_text
    end: int
    quote: str                 # 必须等于 original_text[start:end]

class SourceSpan(BaseModel):
    span_id: str
    parse_id: str
    document_id: str
    section_path: list[str]
    locators: list[SourceLocator]
    original_text: str
    normalized_text: str
    normalization_map: list[dict]
    context_span_ids: list[str]
    issues: list[str]
```

以上是字段契约片段，实施时补齐 import、公共字段和 validators。`original_text` 由 locators 指向的字符片段按固定换行规则拼接；拼接区间映射到对应块、页码和 bbox。`normalization_map` 记录规范化字符区间与原文字符区间的对应关系，插入的检索标题不伪造原文位置。映射不可靠的内容不得自动生成精确引文。

`Citation`：`document_id, title, source_role, parse_id, span_id, page_no, printed_page_label?, bbox, quote, extraction_method`。跨页引文返回 Citation 列表，不以单页坐标覆盖全部文字。

##### 3.4 Chunk

字段：`chunk_id, chunk_build_id, document_id, span_ids[], parent_chunk_id?, role, original_text, retrieval_text, section_path[], token_count, tokenizer_version, text_review_status, linked_clause_ids[]`。

- `role`：parent / child；仅 child 向量化和参与 BM25，parent 用于上下文扩展。
- `text_review_status`：pending / approved / rejected。
- 父块文本由已知来源构成；返回父块上下文前检查其审核资格。
- `retrieval_text` 可包含标题与别名；引用只能取 `original_text` 对应来源。
- 超长条款允许拆子块，但全部指向完整父块；不能完整容纳于模型上下文的条款进入问题队列。

##### 3.5 Entity 与实体提及

`Entity`：`entity_id, canonical_name, entity_type, aliases[], external_ids: dict[str,str], terminology_version, status`。

`entity_type`：disease / syndrome / phenotype / examination / biomarker。

`EntityMention`：`mention_id, text, predicted_type, evidence: EvidenceRef, selected_entity_id?, candidate_entity_ids[], link_method, link_status`。

`link_status`：resolved / ambiguous / local_pending。精确匹配和人工确认可完成链接；模糊匹配只提供候选。外部标准 ID 必须来自词表或已核实映射，不能由模型编造。待确认本地概念可建立 UUID，但关联条款在链接确认前不可发布。

##### 3.6 条件树

使用 Pydantic 可辨识联合类型，按 `kind` 区分以下节点；递归类型通过 `model_rebuild()` 解析：

| kind | 必需字段 | 校验 |
|---|---|---|
| ATOM | field, operator, value, evidence_refs | operator 来自固定枚举 |
| AND / OR | children | 子节点至少 2 个 |
| NOT | child | 恰好 1 个子节点 |
| TEXT | text, evidence_refs, reason | 无法可靠结构化的条件 |

ATOM 可选字段为 `unit, method, population, time_window`。`operator` 为 `eq/ne/gt/gte/lt/lte/in/exists`；`value` 支持 str / bool / Decimal / 同类型列表 / null，其中 exists 的 value 为 bool。数值必须使用严格校验，避免字符串和布尔值被隐式转换。

```json
{
  "kind": "AND",
  "children": [
    {"kind": "ATOM", "field": "finding_a", "operator": "eq", "value": true,
     "evidence_refs": [{"span_id": "s_demo", "start": 0, "end": 1, "quote": "A"}]},
    {"kind": "NOT", "child": {"kind": "ATOM", "field": "finding_b",
     "operator": "eq", "value": true,
     "evidence_refs": [{"span_id": "s_demo", "start": 2, "end": 3, "quote": "B"}]}}
  ]
}
```

示例是结构演示，实际引用必须通过来源校验。没有明确条件使用 `condition=null`，与“条件尚未解析”区分。任何 TEXT 节点使 `condition_executable=false`。首期只保存和验证结构，不执行患者适用性判断；未来求值需要 true / false / unknown 三值语义，缺失事实不能等价于否定。

##### 3.7 CandidateClause 与 ClauseRevision

抽取输出 `CandidateClause` 保存原始实体提及、predicate、条件、例外、字段级 EvidenceRef 和抽取任务信息，不直接写正式图谱。

规范化后 `ClauseRevision`：

| 字段 | 类型 / 约束 |
|---|---|
| clause_id / revision_id / candidate_id | str |
| subject_entity_id / object_entity_id | str；关系需要的实体均已解析 |
| predicate | supports / weakens / associated_with / distinguishes / limits |
| direction | supporting / weakening / neutral / limiting；按 predicate 校验 |
| diagnostic_level | cognitive_state / syndrome / etiology / biological / pathological / unspecified |
| modality | required / recommended / permitted / prohibited / uncertain / unspecified |
| condition | ConditionNode \| null |
| exceptions | list[ConditionNode] |
| condition_executable | bool；仅表示是否已完整结构化，不表示已完成医学验证 |
| evidence_refs | 非空 list[EvidenceRef] |
| field_evidence | dict[str, list[EvidenceRef]]；覆盖关系、条件、阈值等关键字段 |
| assertion_text | str；规范化表述，不冒充原文 |
| review_status | pending / approved / rejected |
| validation_issues | list[ValidationIssue] |
| claim_group_id | str \| null |
| extraction_run_id | str |

将相关性映射为 `associated_with`，不得改写为因果。`distinguishes` 首期仅用于明确疾病对主张，类型矩阵要求两端均为 disease；其他语境不硬套该关系。没有合适关系类型的候选进入 `unsupported_relation` 队列。

`ValidationIssue`：`code, severity, object_id, field_path?, message, evidence_refs[], resolver?`；severity 为 error / warning / info。缺来源、引用不匹配、非法类型、未解析实体为发布阻断项；语义不确定转人工审核，不用模型自报置信度自动放行。

##### 3.8 ReviewDecision、Task 与 Release

`ReviewDecision`：`decision_id, object_type, object_id, expected_revision_id, action, revised_payload?, reviewer_id, reason, decided_at`。action 为 approve / amend / reject。修订必须重跑校验；存在阻断错误时不接受 approve。审核并发时通过 expected_revision_id 阻止覆盖他人修订。

`Task`：`task_id, run_id, stage, input_ids[], cache_key, status, attempt, output_artifacts[], error_code?, error_message?, started_at?, finished_at?`。status 为 pending / running / succeeded / failed / blocked / skipped。人工待审核不是模型失败。

`ReleaseManifest`：`release_id, schema_version, document_ids[], parse_ids[], clause_revision_ids[], chunk_ids[], terminology_version, parser_versions, prompt_hash, extraction_model, embedding_model, embedding_dimension, tokenizer_version, config_hash, artifact_checksums, bm25_path, qdrant_collection, neo4j_release_id, counts, checks, created_at`。

发布状态单独存储为 building / validated / active / retired / failed；不可变 manifest 不随激活状态修改。

#### 4. 存储与图谱映射

##### 4.1 SQLite 权威记录

开启外键，写入使用事务，保存 schema migration 版本。首期表：

| 表 | 主键与主要关联 |
|---|---|
| documents | document_id，checksum 唯一 |
| parses / blocks / spans | 各自 ID；parse→document，block/span→parse |
| span_locators | span_id + ordinal；关联 block |
| chunks / chunk_spans | chunk_id；中间表关联 span |
| entities / mentions | entity_id / mention_id |
| candidates / clauses / clause_revisions | candidate_id / clause_id / revision_id |
| clause_evidence / clause_entities | revision_id + ordinal；关联 span/entity |
| reviews | decision_id；保留对象修订与操作者 |
| tasks / artifacts | task_id / artifact_id；cache_key 成功结果唯一 |
| releases / release_members | release_id；冻结对象修订清单 |
| active_release | 单行活动版本指针 |

嵌套条件和模型返回可存为经过 schema 验证的 JSON；可查询的 ID、状态和来源关系使用独立列或关联表，避免所有内容只塞入 JSON。JSONL 从权威数据导出并记录校验和；禁止直接修改 JSONL 后绕过导入校验。

##### 4.2 Neo4j 投影

节点：Document、SourceSpan、Entity、Clause、Condition。Clause 对应一个 revision。每个发布节点使用 `uid = release_id + ':' + object_id`，设置唯一约束；所有节点和边带 release_id。

| 关系 | 起点 → 终点 |
|---|---|
| PART_OF | SourceSpan → Document |
| SUBJECT / OBJECT | Clause → Entity |
| EVIDENCED_BY | Clause → SourceSpan |
| REQUIRES / HAS_EXCEPTION | Clause → Condition |
| HAS_CHILD | Condition → Condition；保存 ordinal |

predicate、direction、diagnostic_level、modality 放在 Clause 属性中。此图表达与“条款 SUPPORTS 疾病”的语义等价，但使用固定 SUBJECT/OBJECT 结构避免动态关系名扩散。首期不另建无条件 Entity→Entity 临床边。

Neo4j 不支持的嵌套对象不直接写属性：条件递归为节点，完整条件 JSON 可作为辅助字符串保存。使用带 uid 的 MERGE 保证幂等；查询必须携带 release_id。相似主张和冲突候选首期保存在权威记录中，不自动宣布矛盾成立。

#### 5. 分步执行与验收

##### S01：工程骨架、配置与契约

- 输入：现有 pyproject、本文 schema、项目目录规范。
- 实现：创建模块骨架；配置模型；日志；SQLite migration；CLI；模型与存储适配协议。
- 输出：可导入包、默认配置示例、数据库初始结构、schema 导出。
- 接口：`load_config(path) -> BuildConfig`；`init_store(config) -> Repository`。
- 验收：配置错误明确报错；密钥从环境变量读取；空库可初始化；schema 拒绝非法枚举、非法条件树及多余字段。

##### S02：文档导入与快照

- 输入：显式 PDF 路径列表、来源元数据。
- 实现：检查文件可读性、PDF 格式、哈希、快照写入和登记；记录密码保护或损坏错误；不自动扫描全部 paper。
- 输出：Document、source.pdf、登记结果。
- 接口：`register_pdf(path, metadata) -> RegistrationResult`，含 document_id、is_duplicate、issues。
- 验收：重复文件仅一份权威文档；相同名字但不同内容分别登记；原文件未改变；元数据修改有历史。

##### S03：版面解析与 OCR 路由

- 输入：Document 快照、ParseConfig。
- 实现：Docling adapter；正文/表格/页码/坐标转换；按可用文本和质量检查决定 OCR；保存解析器及模型版本。
- 输出：ParsedBlock 列表、blocks.jsonl、页面级 issues。
- 接口：`PdfParser.parse(snapshot_path, config) -> ParsedDocument`。
- 验收：中文、英文、双栏、扫描和表格样本逐类核查；bbox 不越界；阅读顺序可检查；失败页面被明确记录。整文档存在未处理页时不可默认标记完整成功。

##### S04：清洗与原文片段

- 输入：ParsedBlock 列表。
- 实现：识别重复页眉页脚；规范化空白和断行；恢复章节路径；构建 SourceSpan 与位置映射。清洗不覆盖 raw_text。
- 输出：spans.jsonl、清洗统计和问题列表。
- 接口：`build_spans(parsed_document, config) -> SpanBuildResult`。
- 验收：抽样片段可回到原块；跨页片段返回多个位置；页眉删除不误删正文；OCR 引用标注转录来源。

##### S05：父子文本块与抽取上下文

- 输入：SourceSpan、切分规则、tokenizer。
- 实现：条款与表格优先切分；子块关联父块；补充必要表头、脚注和相邻指代上下文；生成独立 retrieval_text。
- 输出：Chunk 列表、chunks.jsonl、待核查上下文问题。
- 接口：`build_chunks(spans, config) -> ChunkBuildResult`；`get_extraction_context(chunk_id) -> ExtractionInput`。
- 验收：每个子块来源非空；条件连接词样本不被无上下文截断；表格行包含表头；超过上限的问题显式入队。

##### S06：开发文本索引与基线检索

- 输入：通过解析质量检查的 child chunks；配置允许 pending 的开发模式。
- 实现：中英文分词、医学别名展开、BM25；EmbeddingClient；Qdrant 开发 collection；RRF 融合。
- 输出：开发索引、检索结果、调用统计。
- 接口：`build_text_index(chunks, index_spec) -> TextIndexManifest`；`search_text(request) -> list[SearchHit]`。
- RRF：`score(d)=Σ 1/(k0+rank_i(d))`，排名从 1 开始，默认 k0=60；两路各取 top 20，按 chunk_id 去重，最终默认 top_k=5。参数写入配置。
- 验收：两路使用同一过滤条件；索引文本数和向量数一致；同模型维度正确；已知证据可用于计算 Recall@k；开发结果明确标记非正式发布。

##### S07：候选条款抽取

- 输入：ExtractionInput，包含原文片段 ID、文本、必要上下文、允许实体类型、关系和输出 schema。
- 实现：可版本化提示词；结构化模型返回；JSON 与 EvidenceRef 校验；缓存；记录原始响应和用量。PDF 内文字作为数据，不执行其中的指令。
- 输出：CandidateClause 列表，允许合法空列表；每个候选附模型/提示词/输入指纹。
- 接口：`extract(context, schema, model_config) -> ExtractionResult`。
- 重试：网络或限流最多 3 次并退避；结构错误最多一次格式修复；不得通过重复调用掩盖长期失败。每次尝试单独记账。
- 验收：空结果与失败可区分；原文没有的字段被标记；引用偏移可检查；断点续跑不重复调用已成功任务。

##### S08：实体归一与条件规范化

- 输入：候选条款、本地术语表。
- 实现：规范名/别名精确匹配；类型约束；歧义候选；新本地实体；条件树结构、数值单位与否定范围检查。
- 输出：Entity、EntityMention、pending ClauseRevision、链接问题。
- 接口：`normalize_candidates(candidates, terminology) -> NormalizationResult`。
- 验收：确认的中英文别名映射到同一 entity_id；相似但不同概念不强制合并；未解析条件为 TEXT；不凭空添加外部本体 ID。

##### S09：一致性校验与相似主张分组

- 输入：pending ClauseRevision 及来源记录。
- 实现：来源与字段证据校验；主体/客体类型矩阵；数值、单位、语气和否定检查；同任务精确去重；跨来源相似主张分组。
- 输出：ValidationReport、审核队列、claim_group_id 与潜在冲突标记。
- 接口：`validate_clause(revision, repository) -> ValidationReport`。
- 验收：引用不匹配、缺实体、错误单位的构造样例被拦截；相同实体不同条件不被删除；不将检查方法不同直接标成医学冲突。

##### S10：文本与条款审核

- 输入：审核队列、带页面定位的证据、当前修订。
- 实现：导出 JSONL/Markdown 审核包；导入结构化决定；校验 reviewer_id；修改生成新 revision；同时提供文本块或文档范围的明确文本批准操作。
- 输出：ReviewDecision、已批准条款修订、文本审核记录、未决队列。
- 接口：`export_review_batch(ids) -> ReviewBatch`；`apply_decisions(decisions) -> ReviewApplyResult`。
- 文本批量批准只表示该范围可进入正式文本检索，不自动批准任何图谱条款；父块上下文也必须处于批准范围。
- 验收：pending/rejected 不进入正式图谱；无来源错误不能被 approve 绕过；旧修订审核冲突报错；修改后的证据重验。

##### S11：双库构建与统一发布

- 输入：经过验证的来源集合、approved 文本块、approved 条款修订、术语版本、模型配置。
- 实现：冻结 release_members；生成发布快照；构建 BM25、独立 Qdrant collection、独立 release_id 图投影；交叉一致性校验；原子切换 SQLite active_release。
- 输出：ReleaseManifest、发布图与索引、checks.json。
- 接口：`build_release(selection) -> ReleaseBuildResult`；`activate_release(release_id) -> ActivationResult`。
- 必须校验：条款引用的来源存在；每条已发布条款至少关联一个已发布文本块且证据片段可读取；所有实体可解析；索引数量/模型维度一致；图与文本 release_id 相同；快照校验和有效。
- 失败策略：任何检查失败均不激活；候选外部数据保留为 failed 供排障。服务每次请求只解析一次活动版本，整次请求使用该版本；旧版本保留到显式回收。
- 验收：注入 Qdrant/Neo4j 写失败时旧版本不变；重复构建无重复节点；可切回上一有效版本；不会读到半发布数据。

##### S12：统一查询、评估与运行说明

- 输入：有效 release_id、查询文本/实体 ID、测试标注集。
- 实现：混合检索、图谱扩展、来源查询、证据包；端到端评估；记录运行命令和环境锁定信息。
- 输出：SearchResponse、EvidencePackage、metrics.json、本附录中的运行说明。
- 接口见第 6 节。
- 验收：单文档全链路完成，再通过 3～5 份中英文 PDF 回归；统计正确引用率、抽取质量和检索召回；无标注项写 not_evaluated，不伪造精度。

#### 6. 外部接口契约

##### 6.1 CLI 设计

下列是计划实现的命令，当前尚不可执行：

```powershell
python -m neurogra.knowledge.cli ingest --pdf "paper/示例.pdf" --metadata "data/knowledge/import.json"
python -m neurogra.knowledge.cli build --document-id <ID> --through chunks
python -m neurogra.knowledge.cli build --document-id <ID> --through candidates
python -m neurogra.knowledge.cli review-export --document-id <ID>
python -m neurogra.knowledge.cli review-import --file <decisions.jsonl>
python -m neurogra.knowledge.cli release-build --selection <selection.json>
python -m neurogra.knowledge.cli release-activate --release-id <ID>
python -m neurogra.knowledge.cli search --query "查询问题" --top-k 5
python -m neurogra.knowledge.cli graph --entity-id <ID> --limit 20
python -m neurogra.knowledge.cli resume --run-id <ID>
python -m neurogra.knowledge.cli evaluate --dataset <annotations.jsonl> --release-id <ID>
```

`import.json` 包含 source_role、title、language 和可选来源字段；`selection.json` 显式指定 document_ids、批准修订集合或审核快照、术语版本和构建配置。参数解析后再次校验审核资格，不能通过手写 selection 绕过审核。

退出码：0 成功；2 参数/配置错误；3 依赖或外部服务失败；4 数据校验失败；5 等待审核或未满足发布条件。输出 JSON 包含 run_id、status、artifacts、issues；人类摘要写 stderr 或单独展示，便于脚本处理。

##### 6.2 Python 服务

```python
search(request: SearchRequest) -> SearchResponse
get_entity_clauses(entity_id: str, release_id: str, limit: int = 20) -> list[ClauseView]
get_evidence(clause_id: str, release_id: str) -> EvidencePackage
get_source(span_id: str, release_id: str) -> SourceView
```

`SearchRequest`：`query, top_k=5, release_id?, source_roles?, document_ids?, mode='hybrid'`。top_k 限制 1～100；默认 source_roles 为临床指南和临床研究；默认只读正式活动版本。开发检索使用单独 CLI/API 入口，不以布尔参数悄悄放宽正式审核过滤。

`SearchResponse`：`query, release_id, hits[], degraded, warnings[], timing_ms`。

`SearchHit`：`chunk_id, score, matched_by[], original_text, retrieval_text, context_text, citations[], clause_ids[], source_role`。融合分数是排序依据，不表示医学可信度。

`EvidencePackage`：`release_id, clause_id, revision_id, assertion_text, subject, predicate, object, condition, exceptions, modality, diagnostic_level, citations[], original_context, review_status`。

图扩展限定为“命中的条款及其实体关联的一跳条款”，默认最多 20 条，并保留已审核、同发布版本过滤。第一版不进行无限遍历或自动诊断推理。

可选单路故障降级必须配置启用：若向量服务失效而 BM25 可用，响应设置 degraded=true 并说明失效通道；不能伪装成完整混合检索。证据或版本完整性失败时禁止降级返回不完整图谱知识。

#### 7. 配置、缓存与失败恢复

配置至少包含：

```yaml
schema_version: "1"
paths:
  data_root: data/knowledge
  output_root: output/knowledge
parsing:
  adapter: docling
  ocr_policy: auto
chunking:
  target_tokens: 450
  max_tokens: 800
  preserve_clause_context: true
extraction:
  provider: null         # 实施时填写，不填则禁止抽取阶段
  model: null
  prompt_version: "v1"
  max_transport_attempts: 3
embedding:
  provider: null
  model: null
  dimension: null
retrieval:
  lexical_top_k: 20
  vector_top_k: 20
  rrf_k: 60
  allow_degraded: false
review:
  require_clause_approval: true
```

分词器、模型上下文上限、批大小、数据库连接、向量距离函数和术语版本在实际 BuildConfig 中补齐必需项。密钥只使用环境变量引用，不进入配置指纹或日志。指纹保存影响结果的非敏感配置。

缓存键包含阶段名称、输入内容哈希、schema、实现版本、提示词、模型、相关参数与术语版本。LLM 请求设置固定参数仍不保证完全确定性，因此保存实际成功响应；显式重新抽取创建新 extraction_run，不覆盖旧结果。

阶段输出先写临时文件，校验后改名并提交 artifacts 记录。启动恢复时核对 running 任务的产物与事务状态，不根据文件存在就认定成功。模型并发和速率限制可配置；首期采用单构建写入者，查询可读已发布快照。

| 变更 | 重跑范围 |
|---|---|
| 新增 PDF | 该文档全部必要阶段 |
| 同 PDF 同配置 | 复用成功产物 |
| 解析/OCR 配置变化 | parse 及所有下游 |
| 切分变化 | spans/chunks 及受影响抽取和索引 |
| 提示词或抽取模型变化 | 抽取及其下游；旧审核结果不自动迁移 |
| 术语表变化 | 实体归一、校验、必要审核和图/文本检索视图 |
| 仅嵌入模型变化 | 向量重建、新发布；无需重做 PDF 与条款抽取 |
| 人工修订 | 新 revision、校验、审核、新发布 |

#### 8. 测试与验收清单

| 测试层 | 必测行为 |
|---|---|
| schema | 条件树、严格值类型、非法关系、空证据 |
| 来源 | Unicode 偏移、跨页、规范化映射、OCR 标记 |
| 切分 | 否定/条件不断义、表头脚注保留、超长上下文 |
| 抽取 | 合法空结果、畸形 JSON、错误引用、超时重试 |
| 归一 | 别名复用、歧义拒识、同名不同类型 |
| 审核 | 未审阻断、修订校验、乐观锁、记录可追踪 |
| 检索 | 中英文分词、过滤一致、RRF 去重、来源返回 |
| 图谱 | 幂等写入、跨版本隔离、条件树节点完整 |
| 发布 | 部分失败不激活、原子切换、旧版本回滚 |
| 续跑 | 重复导入、缓存失效、中断恢复 |

使用固定小型合成 PDF 和模型响应 fixture 验证工程行为，真实样本用于解析与医学抽取质量评价。模型 mock 测试通过不能替代真实抽取评价。

标注集记录 `document_id, span_ids, expected_entities, expected_relations, expected_condition, expected_citations`；检索标注记录 `query_id, query, relevant_span_ids`。开发与独立评估按文档隔离；跨块重复命中的相同证据按 span 去重后计算召回。

指标输出同时给出样本数、分母、错误例子和未评估项。工程门槛见正文第 4.8 节；医学语义准确率和召回目标在首批基线之后写入验收配置，并注明尚未达标项。

#### 9. 里程碑交付与完成定义

| 里程碑 | 对应步骤 | 必须可展示的内容 |
|---|---|---|
| M1 结构化底稿 | S01～S05 | 一份 PDF、原文块、位置映射、父子块和解析问题 |
| M2 文本检索基线 | S06 | 查询命中原文、页码与上下文；开发标识清晰 |
| M3 候选知识与审核 | S07～S10 | 抽取 JSON、实体归一、条件树、审核前后差异 |
| M4 可发布双库 | S11 | 同版文本索引、图谱、manifest 与通过的完整性检查 |
| M5 模块验收 | S12 | 统一查询、真实样本指标、失败恢复、运行说明 |

模块完成意味着：代码与依赖可安装；输入一份已登记 PDF 可以得到可审核底稿；审核后可以发布并查询双库；每条正式条款能回到原文；重复执行和失败恢复经过验证；有真实样本评价和明确局限。仅生成图谱图片或向数据库写入若干节点不视为完成。

实施启动时先确认可用模型服务与本地资源，使用试点 PDF 测量解析结果，再锁定依赖和模型配置。完整网页界面、外部本体扩展和复杂条件求值在此模块验收后于本文更新迭代安排。
