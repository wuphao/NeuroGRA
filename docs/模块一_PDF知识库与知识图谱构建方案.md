# 模块一：PDF 知识库与知识图谱构建方案

日期：2026-09-21  
状态：设计稿，尚未实现或验证。  
配套文档：[详细执行方案](模块一_PDF知识库与知识图谱构建执行方案.md)。

## 1. 目标与项目定位

将用户提供的医学 PDF 转换为可追溯、可检索、可审核、可增量更新的知识底座，同时生成文本知识库和条件化医学知识图谱，为后续鉴别证据检索与证据状态复核提供统一输入。

本方案是现有《算法零：医学文本到 RAG 知识库与条件化知识图谱的构建》的首期工程落地方案。保留条款、条件、原文来源和双库对齐设计，暂缓完整外部本体链接、复杂规则执行和自动冲突裁决。

首期范围围绕认知障碍及阿尔茨海默病、额颞叶变性、路易体相关病因与血管性贡献。第一轮只处理一份中文共识，验证后扩展至 3～5 份中英文指南或共识。

## 2. 输入与最终成果

### 2.1 输入

- 用户明确选择的 PDF 文件，不自动把 `paper/` 下全部论文当作医学依据。
- 文档登记信息：资料用途、标题、来源、年份、语言及已知版本。未知字段保留为空并标记待核查。
- 构建配置：解析器、模型、切分参数、术语表、数据库位置和审核策略。
- 可选的本地医学术语表与人工审核记录。

资料用途分为 `clinical_guideline`、`clinical_research`、`method_reference`。方法论文独立登记；默认医学检索排除方法资料。研究结论保留人群、方法和研究背景，不自动升级为诊断标准。

### 2.2 输出

| 成果 | 主要内容 | 使用方式 |
|---|---|---|
| 结构化文档 | 页面、正文、章节、表格、坐标、解析质量 | 对照 PDF 核查与重新构建 |
| 文本知识库 | 原文块、检索块、BM25 与向量索引 | 返回相关原文、上下文和引用 |
| 条件化图谱 | 实体、条款、条件、例外、出处 | 实体关联与证据关系查询 |
| 审核数据 | 候选知识、校验问题、审核决定及修订历史 | 控制正式知识发布 |
| 发布清单 | 数据、模型、配置与索引版本 | 复现实验、回滚版本 |
| 构建报告 | 数量、耗时、失败项、模型调用与质量统计 | 验收及排障 |

## 3. 总体流程

```text
选择 PDF + 文档登记
          ↓
文件快照、哈希去重、任务登记
          ↓
版面解析 / 必要时 OCR
          ↓
清洗、章节恢复、原文片段、语义切分
          ├──────────────────────┐
          ↓                      ↓
父子文本块                 候选实体与医学条款抽取
          ↓                      ↓
文本质量检查               实体归一、条件结构化
          ↓                      ↓
文本审核                   规则校验、人工审核
          ↓                      ↓
关键词与向量索引           条件化图谱
          └──────────────────────┘
                       ↓
           双库一致性验证与同版本发布
                       ↓
             统一知识查询服务
```

构建链路与在线查询分开。在线服务只读取选定发布版本；正在处理的候选知识不会混入正式结果。

## 4. 核心设计

### 4.1 保留原文和位置

解析器输出必须保留 PDF 物理页码、页面坐标与文本顺序。物理页码统一从 1 开始，印刷页码另存，避免封面、前言造成引用偏移。

解析得到的文本和清洗文本分别保存。扫描件的“原文文本”实际上是 OCR 转录，必须标注获取方式并关联页面区域，不能视为无误的数字原文。低质量 OCR 中的阈值、单位、比较符和否定词需要重点核查。

### 4.2 按语义切分，使用父子块

优先按章节、完整条款、编号列表和带表头的表格行切分。小块参与检索，父块补充完整上下文。300～600 tokens 只是初始可调目标，不能以长度要求破坏条件完整性。

表格保留结构和合并单元格信息；检索文本将行列标题与单元格一起表达，引用仍指向原始单元格区域。无法可靠解释的图表保留位置并登记问题，首期不自动生成正式医学规则。

### 4.3 文本知识库与图谱共享证据底稿

共用 `document_id`、`parse_id`、`span_id`、`clause_id` 和 `release_id`。一个条款可以引用多个原文片段，一个文本块可以关联多个条款。

文本库可以保留没有结构化成条款的有效正文。文本可发布不意味着它已被批准为图谱规则；两者分别记录审核状态。正式图谱首期仅发布已人工通过的条款。

### 4.4 以条款表达医学关系

除同义词等术语关系外，临床主张通过条款节点表达。条款保存主体、关系、客体、方向、诊断层级、语气、条件、例外和原文依据。

结构示例（仅说明数据表达，不是医学结论）：

```text
条款 C → 主体：检查结果 X
       → 关系：支持
       → 客体：疾病 Y
       → 前提：AND(A, NOT(B))
       → 证据：原文片段 S → 文档 D 的第 N 页
```

相同主体和客体但条件不同的主张分别保存。不同来源支持的相似主张只进行分组，不删除各自出处，不把来源数量当作医学证据强度。

### 4.5 抽取、校验与审核

模型根据固定 JSON Schema 抽取候选知识；程序校验结构、原文位置、数值与单位、实体类型和关系约束。字符定位只能证明有对应文本，不能证明模型正确理解了语义。

条件优先保存为 `AND/OR/NOT/ATOM` 树；无法可靠结构化时使用显式 `TEXT` 节点，标记不可执行。禁止通过补全常识生成原文不存在的阈值或关系。

审核者可通过、修改或拒绝候选条款。修改生成新的不可变修订记录，不覆盖审计历史。首期所有正式医学条款需要人工通过；审核接口只保证可记录审核，不代表程序具备医学审核能力。

### 4.6 增量与统一发布

同文件哈希、同阶段配置和同模型版本命中缓存。配置变化仅重跑受影响阶段。第一版以整份变更文档为增量单位，章节级差分作为后续优化。

SQLite 与 JSONL 保存底稿；BM25、Qdrant 和 Neo4j 是可重建的派生索引。先构建独立候选版本并校验，再切换统一活动版本指针。发布失败时旧版本继续服务。

## 5. 技术路线

| 层次 | 首期选择 | 约束 |
|---|---|---|
| 程序 | Python 3.11+ | 遵循现有 `code/` 包布局 |
| PDF | Docling 适配器 | 先验证中文、英文、双栏和表格；低质量页按配置 OCR |
| 数据模型 | Pydantic | 固定 schema，禁止静默忽略模型多余字段 |
| 原始记录 | SQLite + JSONL + PDF 快照 | SQLite 管状态和关联，JSONL 支持审计与重建 |
| 词法检索 | BM25 + 中英文分词适配器 | 记录分词器、词典和参数版本 |
| 语义检索 | Qdrant | 原型可本地模式；并发服务时切换服务端模式 |
| 图谱 | Neo4j | 条款和来源优先，索引按发布版本隔离 |
| 模型调用 | 抽取、嵌入两个独立适配接口 | 实施时根据环境和样本选择模型并锁定版本 |
| 入口 | CLI + Python 查询服务 | 首期不开发完整网页应用 |

模型选择需要用样本比较结构化输出成功率、中英文抽取质量、条件保留率、耗时和费用。没有硬件与模型服务信息前，不承诺具体速度、成本或精度。

## 6. 阶段成果与范围边界

| 阶段 | 交付 | 完成标志 |
|---|---|---|
| A：解析底座 | 来源登记、PDF 快照、结构化页面与文本块 | 单文档原文与位置可核查 |
| B：文本知识库 | BM25、向量检索、引用返回 | 标注问题能够用于测量召回效果 |
| C：条件化图谱 | 条款抽取、实体归一、审核、Neo4j | 已审核主张可回溯到 PDF |
| D：发布与增量 | 双库版本、失败续跑、质量报告 | 重复运行无重复入库，失败发布不影响旧版本 |

第一版不包含患者数据处理、诊断报告生成、治疗推荐、多智能体协作、复杂患者条件求值、全量 UMLS 集成、自动指南替代判断和自动冲突裁决。

## 7. 验收与评价

先选择一份中文共识，人工标注约 50～100 条代表性条款及约 20 个检索问题；之后使用不同文档开展独立验证。小样本仅用于原型评估，不能据此宣称临床有效。

必须满足的工程门槛：

- 已发布条款的来源外键完整，原文区间检查通过率为 100%；定位正确性另外人工抽查。
- 未通过审核条款不出现在正式图谱结果中。
- 重复导入同一文件不新增同版本对象。
- 图谱、文本与引用的发布版本一致。
- 模型失败可重试；无法处理的内容有明确失败记录，不能静默丢失。
- 发布失败保持旧版本可查询，能按发布清单重建索引。

评价指标包含解析质量、实体与关系 Precision/Recall/F1、条件结构完全匹配率、否定与单位保留率、引用正确率、Recall@k、审核耗时和模型调用成本。准确率目标在首批标注和基线测量后确定，不将未经验证的数字写成已达成指标。
