## 2. R01：影像复用与恢复边界

`DiamondResult` 增加内部 `input_binding`，记录患者与病例绑定、病例版本、推理设备、配对窗口，以及按资产 ID 排序的影像路径、内容哈希、模态、序列、示踪剂和时间。历史结果仍可读取；缺少完整绑定的旧成功结果不能作为可验证缓存继续使用。

复用前重新检查当前模型指纹、验证状态、影像准入条件和输入绑定。校验覆盖三处入口：

1. `DiamondTool.predict` 中的同运行结果复用。
2. Executor 中已保存子 Agent 结果的复用。
3. `continue_run` 中恢复运行及直接返回已完成报告之前的成功影像工具结果检查。

不一致时抛出含原因码和 `start_new_run` 的明确异常，并追加审计事件；不会覆盖原推理结果、重新解释旧分数或在原运行中偷偷换模型。用户应使用 `analyze` 启动新运行。原报告文件和 `inspect-run` 仍可作为历史记录查看。

跨运行文件缓存仍校验 CSV 校验和与输入绑定。推理结束时再次核对模型指纹、当前验证状态和文件哈希；验证在执行期间被撤销时，结果失败且预测与分数清空。

新增测试覆盖：原样复用、同路径内容变化、设备变化、模型变化、旧结果缺失绑定、验证撤销、准入条件变化、已完成报告恢复入口、推理期间验证撤销。成功分类路径使用协议测试替身；不将其视为真实模型分类一致性验证。

## 3. R02：可终止的检索执行

`KnowledgeService.search_knowledge(request, deadline=None)` 接收绝对截止时间。ToolProxy 传入子 Agent 的截止时间；独立检索调用默认使用原运行截止时间，调用方不能延长它。

每个后端执行前计算有效截止时间：任务/运行截止时间与后端时限取最早者。向量后端使用 `vector.timeout_seconds`，BM25 与图谱后端使用 35 秒执行上限。

每个后端在独立 Python 工作进程中执行，仅使用只读知识库连接。配置和请求通过标准输入 JSON 传递，不拼接为 shell 命令。Windows 工作进程隐藏窗口，不产生可见控制台。

- 父进程负责预算预留、结果校验、证据落库与结算。
- 工作进程不持有临床运行数据库，不写入临床证据。
- 到期后父进程终止并回收工作进程；收到的迟到结果也会被拒绝。
- SQLite 查询安装进度截止检查；向量请求与图谱查询继续使用各自剩余时间限制。进程边界同时覆盖本地扫描、排序、导入和不可靠的阻塞等待。
- 某个后端失败时保留其他已按时完成的来源；整个任务超时时，不再向子 Agent 返回可用结果。
- 清理存在小幅操作系统开销，不宣称硬实时；终止客户端进程也不等于远端 Ollama 服务一定立即停止内部计算。

测试覆盖：截止时间传递、过期请求不预留预算、不启动操作、原运行期限不能被延长、迟到证据拒绝、真实子进程终止、并行任务互不拖累、部分后端失败后的降级。0.2 秒任务预算的阻塞后端测试要求执行与清理在 0.9 秒内完成。

既有边界单元测试将进程传输替换为直接调用后端，以继续隔离验证来源水合与版本过滤；新增进程测试和真实演示单独验证工作进程路径。

## 4. R03：资料盘点去重

规则阶段仍按句提取候选事实。模型阶段先按唯一 `record_id` 收集原始记录，然后按实际序列化后的 `{"records": [...]}` 长度组织批次，保留 1000 字符余量。

- 同一记录的多句话不再触发重复提交全文。
- 文本相同但来源记录不同的资料分别保留。
- 模型只覆盖部分原文时，剩余文本仍进入快照。
- 模型不可用或预算耗尽时保留规则事实及完整原始记录。
- 超长记录保留原文，并记录 `record_too_large_for_model`；本轮未增加自动长文分段。

测试用 30 句单记录病史验证仅提交一次，另覆盖相同文本不同来源、部分提取、模型失败、预算耗尽和超长记录。
