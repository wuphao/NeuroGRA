# NeuroGRA 项目代码与文档清单

本清单根据当前工作区源码和文件结构整理。主应用是登录后的对话工作台，研究代码、产品原型、论文和运行数据各有独立目录。本轮只建立索引，保留原有文件位置。判断某项功能是否进入主应用，以实际入口和调用链为准。

## 当前应用

| 需要找什么 | 文件和目录 | 用途 |
| --- | --- | --- |
| 安装、启动和使用 | [README](../README.md)、[pyproject.toml](../pyproject.toml)、[依赖锁文件](../requirements/windows-py311.lock) | `neurogra` 命令入口为 `neurogra.platform.cli:main`，Windows 环境与依赖版本在锁文件中。 |
| Web 入口 | [平台 CLI](../code/neurogra/platform/cli.py)、[launcher.py](../code/neurogra/platform/launcher.py)、[server.py](../code/neurogra/platform/server.py) | 启动 HTTP 服务和独立后台进程，处理登录、对话、分析及模型设置接口。 |
| 当前前端 | [平台静态目录](../code/neurogra/platform/static) | `chat.html`、`chat.js`、`chat.css` 是对话界面，另有登录页面和共享报告渲染脚本。旧页面地址跳转至对话。 |
| RWE 登录与患者资料 | [patient_workspace.py](../code/neurogra/platform/patient_workspace.py)、[RWE 客户端](../code/neurogra/clinical/rwe.py)、[项目配置](../configs/rwe.project8.yaml) | 管理登录态、患者授权和只读表单查询。 |
| 普通聊天与记忆 | [patient_chat.py](../code/neurogra/platform/patient_chat.py)、[chat_database.py](../code/neurogra/platform/chat_database.py)、[evochat_store.py](../code/neurogra/platform/evochat_store.py) | 普通会话、账号长期记忆和报告追问。聊天使用项目内 SQLite，长期记忆使用本地 Hermes `MemoryStore`。旧库导入位于 [chat_migration.py](../code/neurogra/platform/chat_migration.py)。 |
| 智能分析与报告 | [patient_analysis.py](../code/neurogra/platform/patient_analysis.py)、[application.py](../code/neurogra/platform/application.py)、[worker.py](../code/neurogra/platform/worker.py)、[store.py](../code/neurogra/platform/store.py) | 选择患者后创建或复用任务，保存输入版本，在后台分析并登记报告产物。 |
| 分析引擎与智能体 | [clinical](../code/neurogra/clinical)、[workflow.py](../code/neurogra/clinical/workflow.py)、[orchestration.py](../code/neurogra/clinical/orchestration.py)、[specialists.py](../code/neurogra/clinical/specialists.py) | 入组与解析、病例分批、主智能体调度、专科分析、知识检索、诊断综合与报告生成。 |
| 模型配置和供应商 | [generation.py](../code/neurogra/clinical/generation.py)、[llm.py](../code/neurogra/clinical/llm.py)、[settings.py](../code/neurogra/platform/settings.py)、[Key 模板](../configs/llm-keys.example.env) | Ollama、OpenRouter、DeepSeek 和 OpenAI 的文本生成协议，以及连接测试、模型列表和设置保存。实际凭据通过本地忽略文件提供。 |
| 知识模块 | [原文 KB](../code/neurogra_kb/README.md)、[条件 KG](../code/neurogra_kg/README.md)、[公共模块](../code/neurogra_common) | KB 提供原文检索，KG 管理图谱构建、存储与检索，共享模块提供标识、结构化协议和模型日志。 |
| 运维与备份 | [平台模块](../code/neurogra/platform) | `preflight.py` 检查环境，`backup.py` 管理备份与恢复，`integrity.py` 检查历史产物，`lifecycle.py` 管理清理与空间。 |

日常改前端从 `platform/static/` 看起。普通聊天从 `patient_chat.py` 追到模型和存储。智能分析从 `patient_analysis.py` 追到后台 Worker，再到 `clinical/workflow.py`。这三条路径覆盖目前对话页面的主要行为。

## 本地数据和生成目录

| 路径 | 内容 |
| --- | --- |
| `data/platform/` | `platform.sqlite` 存平台任务与产物登记，`chat.sqlite` 存聊天会话。`cases/`、`runs/`、`evochat/` 分别用于病例输入、运行结果、长期记忆。 |
| `data/clinical/`、`data/kb/`、`data/kg/`、`data/knowledge/` | 临床工作数据、知识源材料、索引和发布版本。保留数据路径，备份时按项目规则处理。 |
| `output/`、`tmp/` | 本地生成结果、测试目录、临时预览和备份演练。`outputs/` 另存项目设计及变更交付物，两个目录名称接近，职责不同。 |
| `.venv/`、`.ruff_cache/`、`build/`、`__pycache__/`、`*.egg-info/` | 环境、缓存和打包产物。原型目录也有自己的 `node_modules/` 与 `dist/`。 |
| `.env.llm.local`、`.env.rwe.local` | 本地凭据和服务参数。项目清单只记录路径。 |

`clinical/web.py` 仍引用旧 `frontend/` 静态路径，当前工作区未找到该路径，可与 `code/main.py` 等兼容入口一起单独核验。当前工作区还有未提交的应用改动和新文件，清单按实际工作区记录。
