# 基于图谱增强 RAG 与多智能体协作的神经退行性疾病辅助诊疗系统研究

**系统名称：NeuroGRA**  
**文档类型：硕士课题研究方案**  
**日期：2026 年 9 月 17 日**

## 摘要

神经退行性疾病的辅助诊断需要综合病史、认知评估、影像和生物标志物等资料。不同病因可能具有相似表现，病例资料也可能缺失或相互不一致。普通检索增强生成（Retrieval-Augmented Generation，RAG）能够检索相关医学文本，但相关文本不一定能够区分候选病因，也不一定适用于当前病例。

本研究拟开展两项方法研究：**鉴别证据检索（Differential Evidence Retrieval）**，在有限上下文预算内选择具有鉴别价值且适用的证据；**证据状态引导复核（Evidence-State Guided Review）**，根据当前证据的缺口和冲突生成复核请求，调整下一轮检索及允许输出的结论。两项方法通过一次有界反馈形成闭环，多智能体系统承担多模态分析与方法执行。

研究首先核实数据、标签与任务的对应关系，再开展 20–30 个查询的概念验证，随后建立约 100 个高质量查询的小型基准。主要评价固定 token 预算下的鉴别证据覆盖率，以及复核后无依据强结论的变化。当前方案不包含已完成的效果验证。

## 1. 研究问题与范围

### 1.1 两个核心问题

| 问题 | 研究方法 | 需要证明的效果 |
|---|---|---|
| 检索结果与疾病相关，但缺少区分候选病因的关键条款 | 鉴别证据检索 | 相同 token 预算下，覆盖更多适用的鉴别依据，减少重复背景材料 |
| 缺失或冲突条件下，已有证据可能被用于支持过强结论 | 证据状态引导复核 | 复核请求能够改善后续证据与结论，而非仅增加调用或拒答 |

多智能体是两项方法的应用载体。其额外作用通过同模型、同知识库、同病例和同累计预算的单/多智能体对照单独评价。

### 1.2 疾病与输出范围

研究面向认知障碍辅助评估，知识范围包括阿尔茨海默病（AD）、额颞叶变性（FTLD）相关病因、路易体相关病因以及血管性贡献。路易体痴呆（DLB）属于重点鉴别对象；血管性贡献作为鉴别和共存因素纳入，不归类为神经退行性疾病。

系统区分三层判断：

- **认知状态**：认知正常、轻度认知障碍（MCI）、痴呆等。
- **临床综合征**：遗忘主导、行为/执行功能主导、语言主导等。
- **候选病因**：AD、FTLD、路易体相关或血管性贡献，允许多个候选并存。

认知状态与病因不能作为平行类别互相排斥。例如，MCI 与支持 AD 病理的证据可能同时成立；“两种病因均有支持”与“无法在两者之间确定”也应分别表达。AD 诊断标准明确区分生物学与临床维度，可作为分层建模的依据。[1]

首期原型输入临床文本、结构化量表、检验记录以及影像报告或已有工具输出，生成诊断倾向、鉴别依据、资料缺口和下一步评估方向。原始影像模型重训、治疗优化、生成式模态补全和全病种知识图谱不纳入研究范围。仅使用影像报告的实验不声称具有原始影像识别能力。

## 2. 数据、标签与验证任务

**真实病例能够验证的任务由实际标签决定。** 数据申请和字段清点先于完整系统实现。

| 数据条件 | 可以验证的任务 | 不能据此证明的能力 |
|---|---|---|
| 具有多种病因及主要/伴随病因标签的队列 | 病因鉴别、多标签结果及混合贡献分析 | 未覆盖病因或缺少标签的共病判断 |
| 只有 CN/MCI/AD 等标签的队列 | 按数据字典开展认知状态、AD 相关任务及缺失处理 | FTLD、DLB、血管性贡献等真实病例多病因性能 |
| 经审核的鉴别查询与知识条款 | 检索覆盖、条件适用性、证据复核 | 临床诊断准确率或患者获益 |

NACC 是多病因病例的优先候选来源，具体任务需按获批数据版本及主要/伴随病因字段确认；ADNI 可用于 AD 相关任务与多模态资料分析。两者均不能被假定为已经取得权限或全部模态完整。[2][3]

数据清单至少登记数据版本、访问权限、独立患者数、各类标签数、未知标签编码、可用模态和评估时点。同一患者的访视及派生查询必须划入同一集合。诊断目标字段、直接透露目标的结论文本和评估时点之后的信息不进入盲诊输入。未记录病因不能自动作为阴性标签。

若第 3–4 周仍无法确认多病因标签可用，真实病例验证应限定为实际具备标签的任务；知识层面的多病因鉴别检索可以继续开展，但两类结果必须分开报告。

## 3. 方法一：鉴别证据检索

### 3.1 任务与知识表示

该方法接收病例中已知的观测、候选病因对和待解决问题，返回带原文出处与适用条件的证据集合。例如，检索任务不是一般性的“AD 有哪些表现”，而是“当前病例中，哪些知识能够支持 AD 与 DLB 的区分，以及这些知识需要哪些条件”。

知识底座由文本索引和小型**鉴别诊断证据图**组成。图中仅保留疾病、表现、检查、诊断条款、适用条件及原文来源之间的必要关系；每条可执行的关键关系均需核验。知识图用于组织检索，不将图路径直接解释为临床因果或确诊依据。

MedRAG 的层级诊断知识与疾病差异建模、MedGraphRAG 的医学来源关联为该设计提供了基础。[4][5] BM25 关键词检索、向量检索、受限图邻域扩展和排序融合属于基础组件，不单列为研究创新。

### 3.2 三个方法组成

| 组成 | 操作 | 预期作用 |
|---|---|---|
| 候选病因对查询 | 将病例已知信息、两个候选、判断层级和待核对条件组合为查询 | 提高差异条款的召回机会 |
| 条件感知重排 | 根据语义相关性、诊断层级和人群/检测方法等适用条件调整排序 | 降低“相关但不适用”片段的优先级 |
| 证据集合选择 | 在 token 限额内联合考虑条款覆盖与来源重复 | 避免结果集中于某个病因的重复描述 |

首期保留小范围内全部候选病因组，避免早期裁剪漏掉非典型病例。重排先使用固定特征与开发集确定的权重；训练新重排模型作为条件扩展。条件未知与条件不满足分别处理，阴性患者证据与缺失记录分别保留。

### 3.3 集合选择目标

```text
选择证据集合 S，使：
Utility(S) = Σ[d ∈ S] Relevance(d)
           + α × Coverage(S) − β × Redundancy(S)
达到较高值，并满足 Σ[d ∈ S] TokenCost(d) ≤ B。
```

其中，`B` 是允许提供给生成模型的证据上下文预算；`Coverage` 衡量候选对鉴别条款、限制条件等需求的覆盖；`Redundancy` 衡量同源或内容近似的重复。系统采用单位 token 边际收益的贪心选择，不预设最优性保证。

需求项可以包括“区分两种病因的表现”“某检测方法的适用条件”“削弱当前判断的条款”。需求由任务定义和病例已知信息生成，不能为满足配额而编造反证。在线覆盖判断使用审核后的知识关系和固定匹配规则；测试集人工标签仅用于评价。

该设计与通用相关性重排、最大边际相关性（MMR）选择的差别在于，选择目标包含明确的鉴别条款与适用条件。因此，实验必须设置同候选池的 Top-k、MMR 和本文集合选择对照。若未体现额外价值，不能仅凭特征数量或公式形式宣称算法创新。

## 4. 方法二：证据状态引导复核

### 4.1 方法边界

该方法仅回答两个问题：**当前证据状态如何生成复核请求，以及复核请求如何改变下一轮检索和结论输出。**

缺失编码、冲突识别、来源去重和引用检查为方法提供输入。它们属于基础处理，不分别作为算法贡献。研究对象是从状态到复核动作、再到证据和结论更新的过程。

### 4.2 Evidence State 与 ReviewRequest

证据状态（Evidence State）记录当前候选及支持关系、未覆盖条款、患者信息缺口、未决冲突和受影响结论。系统先核对主体、时间、检测方法和判断层级，避免将不可比结果或跨层兼容信息误判为冲突。

复核请求（ReviewRequest）至少包含：**目标候选对、触发证据、待解决问题、所需知识类型、允许动作和受影响结论**。请求必须指向可定位的未决项，不能只是要求模型重复思考。

| 当前状态 | 生成的复核请求 | 对检索和结论的影响 |
|---|---|---|
| 支持材料充分，但缺少候选间差异依据 | 检索指定候选对的鉴别条款 | 改写查询并提高鉴别需求优先级；未解决前保留鉴别不确定性 |
| 知识相关，但检测方法或人群适用性未知 | 查找该条款的适用与限制条件 | 条件未核实前，相关结论只能有条件表达 |
| 同一层级存在可比证据张力 | 检索限制条款与替代解释，核对冲突来源 | 保留两侧证据；不能以 Agent 数量决定取舍 |
| 缺少患者检查或病史信息 | 补取已有资料，或明确待补充项目 | 文献只能说明需要何种信息，不能补成患者事实 |
| 结论引用不能支持其具体表述 | 定位原文并核对支持关系 | 有依据时改写，仍无依据时删除或标为证据不足 |

首期使用可审计的规则产生请求：优先处理会影响关键结论的适用性问题和证据冲突，再处理尚未覆盖的鉴别需求；已处理请求去重。排序规则在开发集固定，不引入强化学习或复杂调度模型。

### 4.3 一次有界反馈

```text
初始查询 → 方法一检索 → 形成证据状态
证据状态 → ReviewRequest
ReviewRequest → 改写查询、更新覆盖目标、标记受影响结论
一次定向复核 → 更新证据状态 → 输出或降低结论强度
```

知识缺口触发新查询；患者资料缺口仅在存在真实资料时补取，否则保留未决。各轮结果按来源组归并，不因重复出现而提高证据权重。流程至多开展一次定向复核，并受整例累计调用预算限制。

结论输出检查来源可定位性、知识适用性、证据支持关系和结论层级。检查结果用于决定保留判断、改为条件性表述、仅陈述事实或报告证据不足。这一过程不将检索得分或模型自报置信度当作患病概率。

该方法的关键对照是：**相同复核次数和累计预算下，固定查询复核与状态驱动复核是否产生不同结果。** 这比比较“一次调用”和“多次调用”更能检验方法本身。

## 6. 验证设计

### 6.1 核心指标：固定预算下的鉴别证据覆盖

方法一的主要指标为 **固定 token 预算下的鉴别证据覆盖率（Differential Evidence Coverage under Fixed Token Budget，DEC@B）**。

```text
DEC@B(q) = 已被预算内证据正确覆盖的鉴别需求数
           ÷ 查询 q 的人工标注鉴别需求总数
```

一项需求被计为覆盖，需检索到能直接回答该需求、出处可定位且关键适用条件未被省略的原文。患者条件未知时，证据可以说明条件要求，但不能被计为已证实患者满足条件。纯疾病介绍、重复片段以及缺少关键条件的片段不能增加覆盖数。主结果按查询宏平均，并按候选病因对分组报告；无适用需求的查询单列，不以满分计入。

主预算可预设为 **3,000 tokens**，具体值经开发阶段确认后冻结。各方法使用相同 tokenizer，按最终传给生成器的全部证据内容计费，包括文本、图谱转写、适用条件和引用元数据；重复内容同样计入。在线选择使用的估计覆盖与人工评价覆盖分别记录，避免用方法自身打分充当实验答案。

报告同时展示逐需求覆盖表，说明增益来自哪些鉴别条款，而非只展示一个均值。Recall@10、nDCG@10、条件适用率和来源冗余作为辅助指标。未运行实验前不预填任何覆盖率或提升百分比。

### 6.2 三个实验包

| 实验包 | 内容 | 主要结果 |
|---|---|---|
| A：鉴别检索 | 相同知识库与预算下比较文本、图检索及本文方法；同候选池比较 Top-k、MMR 与集合选择 | DEC@B、逐条款覆盖及相关性辅助指标 |
| B：状态引导复核 | 使用缺失、真实冲突和跨层兼容场景，比较不复核、固定查询复核、状态驱动复核 | 错误强结论、无依据断言、兼容例误报及回答覆盖率 |
| C：病例与系统 | 在具有实际标签的病例上评价分层判断；开展单/多 Agent 等预算比较 | 分类或多标签指标、引用支持率、成本与延迟 |

错误强结论指证据不足或关键条件未决时仍给出确定性病因判断；它与一般预测错误分别标注。方法二必须同时报告回答覆盖率、关键事实遗漏率和错误率。拒答不从主病例评价中删除；已回答子集的性能单列，避免以少回答获得表面改善。

### 6.3 基线与消融

| 基线 | 配置 | 作用 |
|---|---|---|
| B2 | 单 Agent + 强混合文本 RAG | 文本检索基线 |
| B3 | 单 Agent + 通用图检索 | 区分通用图结构与专门鉴别方法的作用 |
| B5 | 单 Agent + 两项研究方法 | 测量方法本身的效果 |
| B6 | 多 Agent + 两项研究方法 | 测量角色组织的额外作用 |

B3 可采用明确记录配置的受限邻域检索；资源允许时采用 HippoRAG 官方实现，不将自定义适配冒称完整复现。[7] 方法一先独立评价检索，不能仅凭 B5/B2 的最终报告差异推断全部收益来自检索。

最小消融保留五项：去掉候选对查询、去掉条件特征、以 Top-k 替代集合选择、以固定查询替代状态反馈、去掉结论级输出检查。MMR 作为集合选择的直接竞争基线，不新增一套完整系统。

比较控制知识语料、模型版本、病例输入和累计预算。检索实验控制最终证据预算；端到端实验另控制累计检索次数及模型输入/输出 token。各方法报告实际消耗，知识索引建设成本单列。

### 6.4 标注与统计

查询围绕明确候选对编写，包含适用条件、削弱证据和兼容情形，避免全部采用相同模板。标注片段池汇集各方法结果后去重、打乱并隐藏方法身份，必要时补充专家定位条款。

关键留出样本由两位具备相关医学知识的标注者独立判断，分歧仲裁并报告一致性；若仅有研究者标注，须说明资格与限制。LLM 可以预标注，但不独立生成金标准。

开发与留出按患者或条款组隔离，权重、规则及知识版本冻结后再评价。正式结果进行配对比较，按患者或条款组计算置信区间。小规模概念验证只用于可行性和错误分析，不用于宣称临床有效或稳定统计优势。

## 7. 概念验证与实施安排

### 7.1 首个概念验证

第一阶段开展 **20–30 个 AD、FTLD、DLB 相关鉴别查询的 Proof-of-Concept（概念验证）**，不先实现完整多智能体系统。

1. 明确每个查询的候选对、已知条件和应覆盖条款，登记原文来源。
2. 构建只覆盖这些任务的小型知识图和文本索引；留出查询不用于反向补知识或调参。
3. 运行强混合 RAG、普通图检索和鉴别证据检索；用同候选池比较 Top-k、MMR 与集合选择。
4. 在固定 token 预算下记录每项鉴别需求是否覆盖，并归因于召回、适用性判断、重排或集合选择。
5. 若结果未显示价值，先在开发样本上定位瓶颈；调整后使用新留出样本验证，不反复优化同一测试集。

随后扩展至约 100 个高质量查询的小型基准，并引入 30–50 个缺失、冲突或兼容场景评价方法二。正式病例数依据标签分布、可用标注资源和误差区间确定，不预设固定数量目标。

### 7.2 六个月参考进度

| 时间 | 工作与交付物 |
|---|---|
| 第 1 月 | 核实 Dataset × Label × Task；完成 20–30 查询概念验证 |
| 第 2 月 | 建立约 100 查询基准与强基线，冻结首轮评价定义 |
| 第 3 月 | 完成方法一及查询、条件、集合选择消融 |
| 第 4 月 | 完成 ReviewRequest、一次反馈和结论更新，进行方法二对照 |
| 第 5 月 | 集成多模态 Agent，开展真实病例及等预算系统评价 |
| 第 6 月 | 汇总统计、失败案例和适用边界，完成论文与原型展示 |

训练式重排、更多复核轮次、原始影像工具实验和外部队列验证列为条件扩展。计划不包含大型知识图谱、Agent 强化学习、自由辩论优化或治疗策略研究。

## 8. 预期贡献与结论边界

研究拟形成两项方法贡献：其一，将候选病因对、适用条件与预算内证据覆盖纳入鉴别检索；其二，将证据状态转换为具体复核请求，并据此更新检索和结论。NeuroGRA 提供两项方法的多模态执行与可追溯报告原型。

方法价值由基准结果、直接竞争基线和消融验证确定。若集合选择不优于 MMR，则不能仅凭任务化命名主张较强创新；若多 Agent 不优于单 Agent，则其作用限定为模块组织；若缺少多病因病例标签，则研究结论限定于知识鉴别及实际可验证的病例任务。论文按“问题—方法—实验”组织，两项方法分别成章，系统实现与综合评价独立成章。
