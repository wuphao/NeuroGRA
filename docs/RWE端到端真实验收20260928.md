## 报告生成方式

真实运行发现自由改写可能混淆不同检验项目的名称、日期与数值。系统保留被拒绝的模型响应和核对结果，进行一次修订；仍未通过时，由模型从已有事实与允许解释中选择重点和顺序，按对应原始字段直接渲染。

本次两份交付摘要均为 `source_rendered`：事实表达可以直接核查，正文明确标注生成方式。它是带来源的重点概述，不伪装成已经通过核对的自由改写段落。完整字段、专业分析限制和真实检索摘录保存在同一报告及溯源文件中。

本次样例没有保留医学解释性主张。报告主要提供患者来源事实、资料解释条件和未决事项，没有为了形成诊断而强行引用指南。医学诊断性能不在本次流程验收中宣称已验证。

## 约束落实

- 患者编号只用于参数化查询和绑定校验；分析代码没有包含这两位患者的编号或预期结果。
- 量表或表单映射在配置中定义，不补算分数、默认单位或诊断阈值。日期与原始字段保留。
- 表单读取失败、空表单、未填写字段及模型执行失败分别记录。没有将未提供当作阴性。
- 同日同项目不同原值的冲突保留在未决事项和溯源文件，不自动择一。两位真实样例的冲突组均为空，冲突行为另由隔离回归用例验证。
- 凭据、真实导出、数据库及报告均处于 Git 忽略路径。交付文档不包含患者编号、登录密码或 Token。
- 测试替身用于异常边界验证；上表调用统计来自实际 RWE、Ollama 和知识库执行。
