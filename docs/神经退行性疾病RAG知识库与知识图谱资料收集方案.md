# 神经退行性疾病 RAG 知识库与知识图谱资料收集方案

> 适用项目：NeuroGRA——基于图谱增强 RAG 与多智能体协作的神经退行性疾病辅助诊疗系统  
> 建议首期范围：阿尔茨海默病（AD）、额颞叶变性（FTLD）相关综合征、路易体相关病因，以及作为鉴别或共存因素的血管性认知损害。  
> 资料用途：辅助科研与系统验证，不替代临床诊断。本文所列来源在实际采集前仍需核对最新版本、授权范围和机构伦理要求。

## 1. 先明确需要建立的三套数据

NeuroGRA 不应把所有资料直接放入同一个向量库。至少要区分以下三类数据。

| 数据集合 | 主要内容 | 系统用途 | 是否进入 RAG | 是否进入知识图谱 |
|---|---|---|---|---|
| 医学知识语料库 | 指南、诊断标准、共识、系统综述、检查规范、药品说明等 | 为回答和复核提供可引用的医学依据 | 是 | 抽取其中经过审核的关系和条款 |
| 术语与结构化知识库 | 疾病、症状、检查、基因、药物等标准术语及关系 | 实体规范化、图检索、关系扩展 | 只将定义或说明作为辅助文本 | 是 |
| 病例与评价数据集 | 脱敏病历、量表、检验、影像报告、最终诊断及随访 | 构造查询、训练或评价系统 | 原则上不进入公共知识库 | 患者子图须隔离，不能并入通用医学事实图谱 |

核心原则是：**医学知识回答“通常什么条件支持某结论”，患者资料回答“当前病例实际观察到了什么”**。二者必须使用不同标识、权限和更新时间，并在推理阶段临时关联。

## 2. 第一优先级：诊断标准、临床指南和专家共识

这类资料是 RAG 主库和“条件化鉴别证据图”的核心。采集时不能只保存结论句，还要保存前提、必要条件、排除条件、证据等级、适用人群、检查方法及版本。

### 2.1 阿尔茨海默病与认知障碍分层

建议收集：

1. AD 的生物学定义、诊断和分期标准；
2. 主观认知下降、轻度认知障碍和痴呆的临床界定；
3. 典型与非典型 AD 临床表型，如遗忘型、后部皮质萎缩和语言型表现；
4. 淀粉样蛋白、tau 和神经退行性标志物的解释条件；
5. 脑脊液、PET、血液标志物的检测平台、阈值来源和适用场景；
6. AD 与 DLB、FTLD、血管性认知损害、抑郁、谵妄及可逆病因的鉴别条款。

首要来源可采用 Alzheimer’s Association 的 [2024 年 AD 诊断与分期标准入口](https://www.alz.org/research/for_researchers/diagnostic-criteria-guidelines)。该标准强调 AD 的生物学定义，并将生物学诊断与临床表现分开，因此图谱中也应分别建立“疾病生物学状态”和“临床综合征状态”。该页面同时说明该标准不等同于临床实践指南，不能把研究框架无条件改写为临床规则。

### 2.2 路易体相关疾病

建议收集：

- DLB 核心临床特征、支持性特征和指示性生物标志物；
- 认知波动、视幻觉、快速眼动睡眠行为障碍和帕金森综合征的定义与时间关系；
- 多巴胺转运体成像、MIBG 心肌显像、多导睡眠监测等检查的解释条件；
- DLB 与帕金森病痴呆的时间界定；
- DLB 与 AD、血管性认知损害及药物相关症状的鉴别；
- 抗精神病药敏感性等安全相关知识。

首要来源为 DLB Consortium 的 [第四次共识报告](https://pmc.ncbi.nlm.nih.gov/articles/PMC5496518/)。该报告明确区分临床特征和诊断性生物标志物，适合转换为“条款—条件—证据类型—诊断级别”的图结构。

### 2.3 额颞叶变性相关综合征

至少覆盖：

- 行为变异型额颞叶痴呆（bvFTD）的可能、很可能和病理确诊层级；
- 原发性进行性失语（PPA）及语义型、非流利/语法障碍型、词汇减少型三个变体；
- FTLD 与运动神经元病、进行性核上性麻痹、皮质基底节综合征的交叉表现；
- MAPT、GRN、C9orf72 等常见遗传因素及家族史；
- 影像支持模式与临床表型之间的关系；
- bvFTD 与精神障碍、AD、DLB 的鉴别条件。

可从 [bvFTD 国际共识标准原文](https://www.ftdtalk.org/wp-content/uploads/2020/02/RascovskyBrain2011.pdf) 和 [PPA 分类共识](https://pmc.ncbi.nlm.nih.gov/articles/PMC3059138/) 建立首批条款。PPA 共识将临床分类、影像支持和明确病理分层，图谱中不应把这三个层级合并为一个“确诊”关系。

### 2.4 血管性认知损害及混合病因

建议收集：

- 轻度和重度血管性认知障碍的定义；
- 卒中与认知下降的时间联系；
- 执行功能、加工速度及注意功能特征；
- 大血管梗死、腔隙、白质高信号、微出血和战略部位病灶的影像条件；
- 血管危险因素与已经形成的脑血管损害之间的区别；
- AD 与血管病理共存时的表述规则。

基础材料可采用 [VASCOG 2014 标准](https://pmc.ncbi.nlm.nih.gov/articles/PMC4139434/)；后续应补充并核对 2025 年发表的 [VasCog-2-WSO 修订标准](https://jamanetwork.com/journals/jamaneurology/fullarticle/2839119)。由于项目将血管性贡献作为鉴别和共存因素，图谱关系宜使用“支持血管性贡献”“与认知下降存在时间关系”等精确表述，避免简单写成“属于神经退行性疾病”。

### 2.5 中国临床环境资料

国际标准之外，还应收集以下中文权威材料：

- 中华医学会、中华医学会神经病学分会及相关学组发布的认知障碍、AD、DLB、FTD 和血管性认知障碍指南或共识；
- 国家卫生健康委员会发布的诊疗指南、临床路径、检查规范；
- 中国药品说明书、国家药监局安全性公告；
- 国内生物标志物、神经心理量表和影像规范的专家共识；
- 中国人群中的量表常模、教育程度校正和本地语言版本。

中文期刊全文通常受版权约束。获得机构订阅并不等于可以批量复制到可分发语料库。应逐篇记录授权状态；无法取得全文再利用许可时，仅保存题录、摘要、人工整理的结构化条款及合法引用片段。

## 3. 第二优先级：检查、量表和临床表现资料

### 3.1 病史与临床表现

应覆盖发病方式、进展速度、首发症状、认知域、精神行为、运动、睡眠、自主神经、日常生活能力和照护者观察。每项表现至少保留下列属性：

- 标准名称、同义词和否定表达；
- 起始时间、持续时间、频率和严重度；
- 信息来源是患者、照护者、医师观察还是设备；
- 对哪些病因具有支持、反对或仅提示作用；
- 只有在何种组合、时相或阈值下才可使用；
- 可能的药物、精神、代谢或急性疾病混杂因素。

### 3.2 神经心理和功能量表

建议建立“量表目录”，而不是默认把量表题目全文都放入 RAG：

| 领域 | 候选工具 | 需要记录的元数据 |
|---|---|---|
| 全局认知 | MMSE、MoCA | 版本、语言、教育校正、阈值来源、版权 |
| 痴呆分期 | CDR、CDR-SB | 访谈对象、评分规则、培训要求 |
| 日常功能 | ADL、IADL、FAQ | 适用人群、评分方向、照护者信息 |
| 行为精神症状 | NPI 等 | 频率、严重度、照护者负担 |
| 额叶行为 | FAB、FrSBe、CBI-R 等 | 语言版本、常模及授权 |
| DLB 相关 | 认知波动、RBD、帕金森症状工具 | 诊断级别、筛查与确诊差别 |
| 抑郁和谵妄 | GDS、CAM 等 | 用于鉴别或共病，不等同于病因结论 |

量表可能具有版权、培训或商业授权限制。NINDS 的通用 CDE 页面也明确指出，专有量表不会因被推荐而自动开放。因此需要分别保存“量表名称和解释知识”“获授权的题项/评分规则”和“患者分数”，禁止从网页任意复制量表全文。[NINDS 通用 CDE](https://commondataelements.ninds.nih.gov/General%20%28For%20all%20diseases%29)

### 3.3 实验室与生物标志物

资料范围包括：

- 排除可逆或共存因素的基础检验，如血常规、电解质、肝肾功能、甲状腺功能、维生素 B12/叶酸及感染相关检查；
- CSF Aβ42、Aβ42/40、总 tau、p-tau 等；
- 血浆 Aβ、p-tau 亚型、NfL、GFAP 等研究进展；
- APOE 及 FTLD 相关基因；
- 检验前处理、检测平台、样本类型、单位、参考范围和阈值来源。

图谱中不能建立脱离平台的固定阈值。例如“p-tau181 升高”必须关联样本类型、检测平台、实验室参考范围、研究或指南来源和版本。新兴血液标志物应标记为“研究证据”“临床可用”或“指南推荐”等不同成熟度。

### 3.4 神经影像与其他检查

建议收集：

- MRI/CT 的萎缩部位、血管性病灶、脑积水、肿瘤及其他排除性表现；
- FDG-PET、淀粉样蛋白 PET、tau PET 的典型模式和解释边界；
- DAT-SPECT、MIBG 和 PSG 在 DLB 判断中的用途；
- EEG 等检查在快速进展性认知障碍或其他鉴别中的用途；
- 每类检查的采集规范、报告词汇、质量控制和假阳性/假阴性条件。

首期系统输入如果只是影像报告，就只构建“报告发现”节点，不能将其表述为系统直接识别了原始影像。未来接入影像模型时，再增加模型版本、输入序列、质量控制和置信度字段。

## 4. 第三优先级：治疗、安全性和随访资料

即便论文重点是鉴别诊断，也建议保留有限的治疗和安全知识，因为药物既可能影响症状，也可能构成重要禁忌或混杂因素。应收集：

- 已获批药物的适应证、禁忌证、警示、不良反应和监测要求；
- 对症治疗与疾病修饰治疗的证据层级；
- 药物导致认知下降、谵妄、帕金森症状或睡眠异常的可能性；
- 非药物干预和照护建议；
- 复诊、量表变化、功能变化和生物标志物随访建议。

首期图谱只需支持“药物可能导致某表现”“某疾病对某类药物具有安全风险”“某治疗适用于满足特定条件的人群”等关系，不需要扩展成完整临床决策支持系统。

## 5. 术语本体和外部结构化知识

### 5.1 推荐的基础术语源

| 资源 | 建议用途 | 注意事项 |
|---|---|---|
| ICD-10/ICD-11 | 疾病分类、统计编码 | 分类码不能代替细粒度临床知识；核对本地使用版本和授权 |
| SNOMED CT | 临床概念、观察与关系 | 中国地区许可及发行版本需单独确认 |
| UMLS | 多术语映射、CUI 和语义类型 | 需 UTS 账户；组成词表各有许可限制 |
| MeSH | 文献检索词和层级扩展 | 适合查询扩展，不足以单独承担临床图谱 |
| HPO | 症状/表型标准化 | 免费使用但应保留版本、署名且不得擅改原始逻辑关系，[许可说明](https://human-phenotype-ontology.github.io/license.html) |
| Mondo | 疾病统一标识和跨本体映射 | CC BY 4.0，可下载 OWL/OBO/JSON，[下载说明](https://mondo.monarchinitiative.org/pages/download/) |
| HGNC、NCBI Gene、ClinVar | 基因及临床变异 | 区分基因—疾病关联与具体变异致病性 |
| UniProt、Gene Ontology | 蛋白及生物过程 | 主要用于机制层，首期不是诊断图谱核心 |
| RxNorm | 药物名称规范化 | 内容偏美国市场；完整版本和组成词表存在许可约束，[NLM 说明](https://www.nlm.nih.gov/research/umls/rxnorm/docs/termsofservice.html) |
| Open Targets | 靶点—疾病证据 | 更适合机制与科研扩展；开放下载和 API 见[官方文档](https://platform-docs.opentargets.org/data-access) |

建议选用 Mondo 或项目自建疾病 ID 作为疾病主键，HPO 作为表型主键，再保存 ICD、SNOMED CT、UMLS、MeSH 的交叉映射。不能把不同术语库中名称相同的概念自动视为完全等价，所有自动映射都要保留映射类型和置信度。

### 5.2 首期知识图谱实体

首期实体类型建议控制在以下范围：

1. `Disease`：病理性疾病或病因；
2. `Syndrome`：MCI、痴呆、PPA 等临床综合征；
3. `Phenotype`：认知、行为、运动、睡眠和自主神经表现；
4. `Finding`：检验或影像发现；
5. `Test`：量表、实验室检测、影像或生理检查；
6. `Biomarker`：分子、遗传、影像或病理标志物；
7. `Gene` 与 `Variant`；
8. `Drug` 与 `Intervention`；
9. `RiskFactor` 与 `Comorbidity`；
10. `CriterionSet`、`Clause`、`Condition` 和 `Exception`；
11. `SourceDocument`、`SourceSpan`、`Organization` 和 `Version`。

### 5.3 首期核心关系

```text
Disease --has_phenotype--> Phenotype
Disease --has_biomarker--> Biomarker
Disease --associated_with_gene--> Gene
Syndrome --may_be_caused_by--> Disease
Finding --supports_under_condition--> Disease
Finding --argues_against_under_condition--> Disease
Finding --differentiates--> DiseasePair
Test --measures--> Biomarker_or_Phenotype
Test --requires_method--> Method
Clause --requires--> Condition
Clause --has_exception--> Exception
Clause --supports_level--> DiagnosticLevel
Clause --derived_from--> SourceSpan
SourceSpan --part_of--> SourceDocument
SourceDocument --issued_by--> Organization
SourceDocument --supersedes--> SourceDocument
Drug --may_cause--> Phenotype
Drug --has_safety_issue_in--> Disease_or_Condition
```

“supports”关系不能只连接两个节点。它至少还应携带适用条件、证据方向、诊断层级、来源定位、发布日期、审核状态和置信度，否则无法支持论文提出的条件感知检索。

## 6. 文献资料的范围与采集方式

### 6.1 应收集的文献类型

按优先顺序建议为：

1. 国际或国家级诊断标准和临床指南；
2. 专业学会专家共识及检查规范；
3. 系统综述和高质量循证综述；
4. 关键生物标志物、鉴别诊断和纵向队列研究；
5. 病理—临床对应研究；
6. 典型病例系列，仅用于发现少见表现和关系候选；
7. 教材、患者教育网页和百科，用于术语解释，不作为高等级诊断依据。

### 6.2 文献入库范围

PubMed 题录、关键词和摘要可用于检索索引及筛选；全文语料优先使用 PMC Open Access 子集或明确取得许可的文献。PMC 明确要求自动化获取使用其官方 API，并且并非所有 PMC 文章都允许文本挖掘或再分发，因此要逐篇保存许可信息。[PMC 开发者说明](https://pmc.ncbi.nlm.nih.gov/tools/developers/)

每篇文档至少保存以下元数据：

```text
document_id, title, authors, organization, document_type,
publication_date, effective_date, version, language,
doi_or_url, license, acquisition_method, supersedes,
population, disease_scope, evidence_level, reviewer,
review_status, checksum, indexed_at
```

每个切片应额外保存章节标题、页码或段落号、字符范围、表格/图编号、上级条款、引用链和原文哈希。不要按固定字符数把诊断条款及其条件拆开。

## 7. 病例和评价数据集

病例数据主要用于系统评测，不应作为可引用医学知识。对于本课题，优先级最高的不是海量原始 MRI，而是具有**多病因、纵向随访、结构化临床评估和最终诊断**的数据。

| 数据源 | 可用内容 | 对本项目的价值 | 约束或风险 |
|---|---|---|---|
| NACC | 纵向临床评估、神经心理、诊断、病理、影像及生物标志物；另有 FTLD 和 LBD 模块 | 与 AD、FTLD、LBD 多病因范围最匹配，可建立鉴别和随访任务 | 需按流程申请；不同中心的数据完整性和采集频率不同。参见 [NACC Researcher’s Guide](https://www.naccdata.org/the-nacc-researchers-guide) |
| ADNI | 临床、认知、MRI/PET、生物体液、遗传和病理等纵向数据 | 适合 AD 连续谱和多模态一致性验证 | 需申请并遵守数据使用和发表政策，[ADNI 数据页](https://adni.loni.usc.edu/data-samples/adni-data/) |
| OASIS | 多批次 MRI、临床及认知资料 | 可用于影像相关扩展与公开基线 | 数据集之间范围不同；受数据使用协议和当前地域访问政策限制，[访问条款](https://sites.wustl.edu/oasisbrains/home/access/) |
| NINDS CDE/PDBP | 通用神经病学数据元素、帕金森病数据字典和表单 | 用于设计统一字段、允许值和 CRF，不应当作病例队列 | 某些量表仍有独立版权。[NINDS CDE](https://www.ninds.nih.gov/current-research/scientific-resources/ninds-common-data-elements) |
| 本地医院回顾性病例 | 中文病史、报告、检验、实际缺失模式和鉴别过程 | 最符合最终应用环境 | 必须通过伦理审批、脱敏、访问控制和数据使用协议 |
| 专家编写或公开病例 | 可控制缺失、冲突和罕见鉴别条件 | 适合构造挑战集和错误分析 | 必须标记为合成/教学病例，不能与真实病例性能混报 |

NACC 的资料结构尤其适合本项目，因为其公开说明中包含 UDS、FTLD 模块和 LBD 模块，并明确区分病因诊断与认知状态。ADNI 更适合 AD 生物标志物和纵向变化，但不足以单独评价 FTLD、DLB 与血管性贡献之间的全面鉴别。

### 7.1 每个病例至少需要的字段

- 基本人口学信息及教育程度；
- 主诉、发病年龄、病程、进展模式；
- 患者和知情者提供的病史；
- 各认知域和神经精神表现；
- 日常生活能力；
- 神经系统查体、运动、睡眠和自主神经表现；
- 量表原始分、总分、版本、语言和日期；
- 实验室数据的数值、单位、参考范围、方法和日期；
- 影像报告、检查日期和必要时的结构化标签；
- 用药、共病及潜在混杂因素；
- 每次随访时的综合征状态、候选病因及确定程度；
- 最终诊断依据、病理或遗传证据；
- 缺失原因，而不是把缺失字段记成阴性。

## 8. 针对两项关键算法必须额外标注的资料

### 8.1 条件感知的鉴别证据检索

为评价“是否找到了真正能区分候选病因的证据”，需要人工建立一个小而可靠的鉴别证据金标准。每个候选疾病对应至少标注：

- 鉴别需求；
- 应检索到的条款；
- 条款适用条件和例外；
- 支持、反对、限制解释或仅提示补检查的用途；
- 来源和精确定位；
- 哪些证据内容重复，哪些虽然同源但属于不同必要条款；
- 在限定 token 预算下不可缺少的证据包。

例如 AD 与 DLB 的鉴别不能只标注“视幻觉—DLB”，还需要标注出现时间、反复性、是否成形、药物或谵妄等替代解释，以及它在对应标准中的诊断地位。

### 8.2 证据状态引导的有界复核

需要构建含下列情形的病例或问题集：

- 医学知识没有检索到，但患者资料已经存在；
- 医学条款存在，但患者未做相关检查；
- 患者已做检查，但方法、单位或日期缺失；
- 两条证据表面冲突，实际上人群、方法或时点不同；
- 支持和反对证据均存在，复核后仍不能消除；
- 引用过期、被新标准替代或无法定位；
- 复核不能解决问题，系统应保留多候选或降低结论强度。

每条样本应标注正确动作：重新检索医学知识、补取已有患者资料、提示未来采集、重新比较证据、调整结论或保持不确定。这样才能评价“是否采取了正确复核动作”，而非只评价最后诊断是否碰巧正确。

## 9. 资料质量、版本与授权管理

### 9.1 来源等级

建议采用以下内部等级，但不要把等级直接解释为某个患者结论的概率：

```text
A：正式诊断标准、循证临床指南、监管机构文件
B：专业学会共识、系统综述、标准化检查规范
C：高质量原始研究、纵向队列、病理验证研究
D：病例系列、叙述性综述、教材
E：患者教育材料、普通网页和未经审查内容
```

A 级来源也可能不适用于当前患者；C 级研究也可能提供某一新生物标志物的重要证据。因此最终排序应同时考虑来源等级、条款适用性、发表时间和任务相关性。

### 9.2 每条知识的审核状态

```text
machine_extracted → terminology_aligned → human_reviewed
→ clinically_reviewed → active / superseded / rejected
```

自动抽取内容在完成临床审核前不能作为高确定性诊断规则。新版本发布后，应将旧条款标记为 `superseded`，保留历史关联，不能直接覆盖或删除。

### 9.3 版权、伦理和隐私

- 文献全文、量表、药物数据库和术语库分别核对许可；
- 保存来源许可、版本日期和访问方式；
- 真实患者资料必须经伦理审批和充分脱敏；
- 通用医学图谱与患者子图物理或逻辑隔离；
- 不把受限数据上传到未经批准的外部模型服务；
- 对训练、调参和测试病例按患者划分，避免同一患者不同访视跨集合泄漏；
- 发布模型或知识库时，不随包分发授权不允许再发布的原文或量表题项。

## 10. 推荐的首期最小资料包

为了使硕士论文范围可完成，不建议一开始建设覆盖全部神经退行性疾病的大图谱。可先完成以下最小集合：

### P0：必须完成

1. AD、DLB、bvFTD、PPA 和血管性认知损害的核心诊断标准；
2. 每类疾病 1 至 2 份高质量中文指南或共识；
3. 认知状态、核心临床表现、常用检查和生物标志物术语表；
4. AD—DLB、AD—FTLD、AD—血管性、DLB—FTLD 四组重点鉴别关系；
5. 每个诊断条款的条件、例外、来源定位及版本；
6. 经过专家审核的 100 至 300 个鉴别证据包；
7. 一组专门包含缺失、冲突和过期引用的复核评价样本；
8. 一套独立病例测试集，病例内容不进入 RAG 知识库。

### P1：论文实验稳定后扩展

- 更多中文真实世界资料和本地常模；
- 血液生物标志物平台差异；
- FTLD 遗传与病理关系；
- 药物安全性及可逆性认知障碍；
- 纵向状态变化和混合病理。

### P2：后续研究

- 原始 MRI/PET 模型输出；
- 蛋白、通路和多组学机制图谱；
- 全神经退行性疾病范围；
- 治疗推荐和疗效预测。

## 11. 建议的实际收集顺序

1. 固定疾病范围和诊断层级，先编制来源清单；
2. 下载或登记五类核心诊断标准，记录版本与许可；
3. 建立疾病、综合征、表型、检查和生物标志物词表；
4. 以四组重点鉴别对为单位人工整理条款；
5. 将条款连同条件、例外和原文定位写入结构化表；
6. 经医学人员审核后生成图谱边和 RAG 证据包；
7. 再补充综述与原始研究，不让低等级来源覆盖正式标准；
8. 单独准备病例评价集及缺失/冲突挑战集；
9. 冻结知识库版本，记录实验所用文档、图谱和病例版本；
10. 论文实验完成后再扩充病种和机制层知识。

按照这一顺序，最先得到的不是一个规模很大但关系含混的医学图谱，而是一套能够支撑“条件完整检索”和“证据状态复核”的小型高质量知识底座，这与 NeuroGRA 两项核心算法的验证目标直接对应。
