| P2 | `clinical/utils.py` | 同一患者的两个运行同时写 input.json，共用固定 .tmp 路径，可能覆盖或移动对方临时文件 | 使用唯一临时文件，写完后原子替换，并清理临时文件 |

## 兼容性与验证边界

- 已发布解析记录现在拒绝破坏性重解析。重新构建需要新的解析配置或解析器版本，以生成新的 parse_id；未发布数据仍可重解析。这也会让对已发布 PDF 直接重跑构建脚本返回明确错误。
- 新发布使用包含内容与术语版本的 ID；已有发布的 ID 和数据未迁移。旧发布文件若缺少所需校验和或已损坏，检索会明确报错。
- 已保留的良好设计包括 SQL 参数绑定、患者附件目录限制、子进程参数列表调用、持久化预算和 DiaMond 验证门控。
- 本次验证使用临时数据及模拟响应；没有调用真实 Ollama、Neo4j 或 DiaMond 推理，没有浏览器视觉验收。现有复查输入长度限制和 DiaMond 验证阻断仍需独立集成验收。
- 全项目审查围绕主要执行路径和风险点展开，不等同于对所有可能输入、依赖库漏洞或并发交错作形式化证明。
