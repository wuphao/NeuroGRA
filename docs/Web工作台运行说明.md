# NeuroGRA Web 工作台

## 启动

在项目根目录执行：

```powershell
python -m neurogra.clinical.web --port 8767
```

访问 <http://127.0.0.1:8767/>。

沿用 `configs/clinical.rwe.yaml` 与 `configs/rwe.project8.yaml` 的配置。
RWE 后端、数据库、Ollama 与知识检索依赖需按现有运行说明启动。
凭据继续从本地配置读取，不发送到前端。

## 操作流程

1. 输入 RWE 的 `patient_number`（患者编号，不是数据库内部主键）。
2. 点击“开始分析”。服务实际读取 RWE 资料并调用现有智能体流程。
3. 页面每 3 秒读取真实状态及调用次数，不模拟百分比或固定执行时长。
4. 分析完成后自动打开综合报告，分别显示执行状态与医学评估状态。
5. 在“事实与结论”中搜索陈述并查看原始观察、字段定位和知识依据。
6. 在“知识来源”中查看完整引用、页码、适用条件与限制。
7. 使用“分析记录”打开历史任务与已有报告；“导出报告”下载当前 JSON。

报告内容来自最终报告和对应的溯源文件，不按患者编号匹配预写答案。
没有患者、RWE 鉴权失效、读取失败等情况会呈现任务失败信息，不回退到演示报告。
批次级待核查意见保留其范围说明，不作为已确认的患者事实。

## 任务行为

- 全局同时允许一个 Web 分析任务；重复提交同一患者返回同一活动任务。
- 任务记录存入现有 SQLite 的 `web_jobs` 表，页面关闭不取消后台任务。
- 浏览器只保存活动任务 ID，刷新后重新请求服务端状态与报告。
- 服务进程终止后，重启将未完成的 Web 任务标记为中断；不会静默重置预算或重复执行。用户可重新发起分析。
- 历史列表包含此前命令行生成的最终报告。
- 仅监听 `127.0.0.1`，供本机使用；接口包含 Host/Origin 校验、跨站请求拦截和启动会话 Token。
- 服务只提供固定页面资源与报告接口，不开放项目目录、凭据或任意文件下载。

## 接口

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET | `/api/session` | 获取当前本机会话 Token |
| POST | `/api/jobs` | 提交 `{"patient_number":"..."}`，携带 `X-Workbench-Token` |
| GET | `/api/jobs` | 任务和既有报告列表 |
| GET | `/api/jobs/{job_id}` | 任务状态、实际调用统计与近期事件 |
| GET | `/api/reports/{run_id}` | 匹配的最终报告、依据与执行记录 |
