## 1. 当前研究现状

### 1.1 已有技术已经走到哪里

医疗 RAG 已经从检索相似文本，发展到利用图结构组织知识、根据证据缺口继续检索，以及通过多个角色核查并整合答案。因此，NeuroGRA 的研究重点不能停留在把知识图谱、RAG 和多智能体连接起来，而应回答：**这些组件如何在具体病例中找到真正有鉴别价值的证据，并正确处理证据的使用条件。**

| 技术方向 | 已有工作及其能力 | 对本研究的启示 |
|---|---|---|
| 文本与图联合检索 | GraphRAG、LightRAG 等利用关系或层次组织检索；Medical Graph RAG 进一步关联医学来源和术语定义 | 图结构和来源追踪可作为基础，但不能直接证明返回的知识适用于当前患者。[W1][W2][L2] |
| 疾病差异知识检索 | Zhao 等人的 MedRAG 建立四层诊断图谱，检索疾病差异信息，并生成后续问题 | “鉴别图谱”和“追问”已经存在，本文需进一步研究条件完整性和预算内证据选择。[L1] |
| 证据反馈与迭代检索 | SEMA-RAG 将临床约束、充分性判断、缺口查询和证据裁决分配给不同角色 | “发现不足后再检索”本身不是新增贡献，必须明确何种不足对应何种动作。[L3] |
| 指南与多智能体协作 | MedCoRAG 联合指南和图路径，进行路径修剪及证据不足时的定向检索 | 指南约束、图谱和多专科角色的组合也有接近工作；本文应检验更具体的条款与状态机制。[W8] |

这里所说的不足，是上述方法直接用于本项目时仍需检验的环节，不等于这些论文完全没有考虑适用性、冲突或证据质量。

### 1.2 本地中文论文已经覆盖了哪些内容

| 本地论文 | 已有研究重点 | NeuroGRA 应继续深入的部分 |
|---|---|---|
| 高福财：医疗辅助诊断系统 | 全局修剪图检索、路径连接、原子声明分解与事实核查 | 从相关路径筛选转向完整鉴别条款选择，并让核查结果改变下一步检索。[L5] |
| 姚行志：医疗图谱扩充与应用 | 动态示例、自反思抽取、实体对齐，以及文本生成后的图谱矫正 | 关键条款由原文与审核支撑；复核由具体缺口驱动，避免只围绕初始答案扩展。[L6] |
| 王梦涵：知识图谱问答 | 自我验证、多轮路径修正、问题分解和迭代图检索 | 将一般路径验证细化为条款条件、患者事实和受影响结论的核对。[L7] |
| 刘览：病案质检 | 医疗指令微调、规则知识库、GraphRAG 及中文医学抽取适配 | 研究对象转为候选病因之间的鉴别，重点评价证据覆盖与条件误用。[L8] |
| 卿正：图谱与大模型问答 | 领域图谱、KGQA/RAG/LLM 多通道及复杂度路由 | 检索与复核动作由证据状态决定，而不仅根据问题难度选择通道。[L9] |

由此可见，构图、混合检索、反思、核查和多轮问答已有较充分基础。本项目的差异应体现在**检索什么、依据哪些条件选择证据，以及缺口如何改变下一步动作和结论**。

### 1.3 神经退行性疾病场景中的具体问题

对于认知障碍辅助评估，不同病因可能共享症状，病史、量表、检验及影像报告也可能不完整。检索到相关医学知识之后，仍有两类关键问题：

**第一类：相关，却不足以鉴别。** 返回大量一般症状介绍，但没有覆盖候选病因之间真正需要核对的条款；或者找到了条款，却漏掉检测方法、人群、时间等前提。在有限上下文中，重复背景会挤占关键依据。

**第二类：证据未决，却形成过强结论。** 模型没有区分知识没有检索到、患者没有做检查、资料未记录和真实证据冲突，因而可能把未知当满足、把未记录当阴性，或者在不同层级的信息之间制造假冲突。

这两类问题对应原方案已经确定的两项研究方法，下面保持这一目标不变。

## 2. 本项目要解决的目标

### 2.1 总体目标

构建面向神经退行性疾病辅助诊疗的 NeuroGRA 系统：利用图谱增强 RAG 获取有鉴别价值且适用的医学依据，通过证据状态引导复核，形成可以追踪患者事实和医学来源的分层判断。

多智能体承担不同模态的分析与流程执行。研究贡献优先围绕下面两项方法展开。

| 研究问题 | 对应算法 | 希望实现的结果 | 主要验证方式 |
|---|---|---|---|
| 有限上下文中缺少适用的鉴别条款 | **算法一：鉴别证据检索** | 检索并选择能区分候选、条件完整、来源明确的证据集合 | 同知识与 token 预算下的鉴别证据覆盖率，以及条件误用情况 |
| 缺失、冲突或引用不支持时仍输出过强结论 | **算法二：证据状态引导复核** | 将具体未决项转换为明确复核动作，并更新受影响结论 | 同复核次数及累计预算下的错误强结论、问题解决率和回答覆盖率 |

### 2.2 研究范围

疾病知识范围沿用原方案：AD、FTLD 相关病因、路易体相关病因，以及作为鉴别和共存因素的血管性贡献。血管性贡献不归类为神经退行性疾病。

首期输入包括临床文本、结构化量表、检验记录、影像报告或已有工具输出。系统输出分三层：

- **认知状态**：正常、MCI、痴呆等。
- **临床综合征**：遗忘、语言、行为/执行等主导表现。
- **候选病因**：允许多个候选并存，分别说明支持、限制和资料缺口。

三层不能作为一组互斥类别；生物学证据与临床状态也应分开理解。[C1] 首期不扩展到原始影像模型重训、治疗策略优化和全病种知识图谱。

### 2.3 如何判断目标是否实现

算法一需要优于强混合文本检索及同候选池的 Top-k/MMR；还需与包含相同条款和条件的平铺检索比较，确认收益是否来自图关系。

算法二需要与固定查询复核、一般缺口反馈比较。仅增加调用、减少回答或采用更保守的措辞，都不足以单独证明有效。

真实病例任务由实际标签决定：仅有 CN/MCI/AD 标签时，不据此声称验证了 FTLD、DLB 的多病因鉴别。知识层检索评价和临床病例评价分别报告。

## 3. 系统整体架构

### 3.1 架构图

![NeuroGRA 系统整体架构](<D:/Python Project/NeuroGRA/docs/assets/NeuroGRA_系统整体架构.png>)

**图 1：NeuroGRA 整体架构。** 右侧离线知识底座为算法一提供条款和原文；左侧在线流程从病例分析进入两项核心算法。算法二最多触发一次定向复核批次，结果回到证据状态和结论检查，最终生成报告。

### 3.2 各部分承担什么工作

| 部分 | 核心职责 | 交给下一步的结果 |
|---|---|---|
| 病例输入与多模态分析 | 从可用病史、认知、影像报告和检验中提取事实，保留来源、时间、缺失及矛盾 | 结构化发现、候选病因对、初始证据需求 |
| 共享知识底座 | 将指南等来源组织为条款、适用条件、例外与出处；维护文本索引和鉴别证据图 | 同一版本的可核验知识 |
| **算法一** | 候选对查询、文本/图召回、条件核对、预算内证据集合选择 | 完整证据包、适用状态、未覆盖需求 |
| **算法二** | 建立证据状态、区分缺口类型、执行有界复核、更新结论限制 | 更新后的证据与允许输出的结论 |
| 分层报告 | 表达认知状态、综合征、候选病因及支持/限制依据 | 可追溯报告、资料缺口与下一步评估方向 |

病史、认知、影像和检验角色共享同一证据服务。没有对应数据时不启动该模态分析；角色结论不采用简单多数投票。数据库、框架和接口实现先按原型需要选择，本阶段不作为研究重点。

### 3.3 一次完整处理流程

1. **提取患者事实。** 整理可用资料，区分已观察、明确否认、未测、未记录和不确定。
2. **形成鉴别需求。** 根据患者事实、判断层级和候选病因对，明确需要哪些差异、条件及限制条款。
3. **执行算法一。** 联合文本与图检索，选择预算内完整证据包。
4. **形成初步结论与状态。** 将每条结论关联到患者观测和知识条款，标记缺口或冲突。
5. **执行算法二。** 知识不足时定向重检索；已有患者资料可补取时读取原记录；没有资料时保留未决。统一限制为至多一次复核批次。
6. **输出报告。** 按更新后的状态控制表述强度，给出三层判断、依据和资料缺口。

两项算法的接口是明确的：**算法一交付“证据及其状态”；算法二返回“需要补什么、允许怎样补、哪些结论必须调整”。**
