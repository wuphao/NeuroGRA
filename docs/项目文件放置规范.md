# 项目文件放置规范

更新日期：2026-10-08。新增内容优先更新现有文档，保持当前设计只有一套入口。旧设计、重复副本和历史交付记录按清理清单删除；需要恢复时使用本地恢复备份。

| 目录 | 用途 |
| --- | --- |
| `code/` | 项目源码、测试及维护脚本。构建生成的 egg-info、缓存不提交。 |
| `configs/` | 不含真实凭据的配置及示例。 |
| `frontend/` | 工作台页面、脚本及前端说明。 |
| `docs/` | 当前总体方案、构建方法、临床工程及运行说明。 |
| `docs/知识图谱设计/` | 图谱结构 v0.3、统一算法 v1.0、来源边界、五步说明及抽取配置。 |
| `docs/assets/` | 当前文档使用的图片和可编辑源文件。删文档时检查专属旧图。 |
| `docs/开题报告/` | 正式开题报告和答辩设计；工作 PPT 按实际版本维护。 |
| `docs/reviews/` | 仍有引用价值的背景综述及本次清理记录。 |
| `docs/references/` | 诊断文献原件、来源清单和目录，同一资料不重复保留 ZIP。 |
| `data/` | 原始数据、知识发布、图谱和索引等本地数据，默认忽略。 |
| `output/` | 运行产物、文档导出与渲染检查，默认忽略。正式交付文件与编辑源稿用途分别标明。 |
| `paper/` | 研究论文、指南及阅读笔记，默认忽略；已有跟踪笔记保持原状态。 |
| `study/` | 个人学习材料，项目代码不依赖此目录。 |
| `tmp/` | 可再生成的中间文件及恢复备份，默认忽略。删除前检查是否还有唯一编辑源稿。 |
| `OptimusKG/`、`RAG-Anything/`、`RTX-KG2/` | GitHub 下载的本地参考源码，整目录忽略，独立获取和管理。 |

总体方案使用 `docs/总体设计.md`。图谱契约以 v0.3 为准，问答方法以统一算法 v1.0 为准；算法零第 12 节维护当前文献抽取流程，主子 Agent 设计维护临床复查及未完成任务，RWE/Web 文档维护运行入口。

同一正文以 Markdown 或明确的编辑源稿为主，Word/PPT 是按用途维护的交付材料。方法修改后同步短版与需再次使用的开题材料，不另存“最终版2”。研究设计、当前代码和历史验收结论须区分，不能把过去测试数量写成当前测试结果。

`.env*`、患者数据、临床报告、模型和索引只在本地保存。根目录保留 README、项目配置和版本管理文件。新增文件使用清楚的主题名，日期推荐 `YYYY-MM-DD`。

修改或删除后检查相对链接、图片、抽取配置和构建脚本引用。外部源码引用保留原项目来源及所用版本；加入 `.gitignore` 不会自动停止已跟踪文件的跟踪，也不会自动清除历史。
