# 算法一：鉴别证据检索详细设计

配置说明：本文的候选池、查询数、证据预算及复核次数为开发起点，实验前冻结；总体范围与跨模块执行口径以《总结设计》为准。

返回：[总体设计](总结设计.md)

后续算法：[算法二：证据状态引导复核详细设计](<D:/Python Project/NeuroGRA/docs/算法二_证据状态引导复核详细设计.md>)

本文只讨论第一项关键算法：如何在固定上下文预算内，找到并选择具有鉴别价值且适用于当前病例的证据。公式使用纯文本记法，不依赖 LaTeX；所有参数与收益均为待验证设计。

## 1. 算法要解决的问题

普通检索容易返回与疾病相关的描述，却未必覆盖当前候选病因之间的差异；同时，一条看似相关的知识可能有检测方法、人群或时间限制。因此，检索目标是**完整、适用且有鉴别价值的证据集合**，而不只是相关片段的排名。

算法的三个关键环节是：以候选病因对构造查询；核对条款条件并区分证据用途；在 token 预算内联合优化鉴别需求覆盖与内容重复。

```text
患者观测 + 候选病因对 + 判断层级
                 |
                 v
生成证据需求和查询
                 |
                 v
文本召回 + 受限图检索
                 |
                 v
构造完整证据包，核对适用条件
                 |
                 v
相关性重排 + 预算内集合选择
                 |
                 v
证据包 + 适用状态 + 未覆盖需求 → 算法二
```

## 2. 算法依赖的知识与数据表示

### 2.1 为什么需要条款节点

普通三元组 `(疾病，相关表现，某表现)` 不足以表达：这一关联适用于哪类人群、采用哪种检测、是支持还是排除、属于哪一判断层级、有何例外、原文在哪里。

建议把原文中的一条可核验医学主张重新表示为 **Clause 节点**，再连接疾病、表现、条件和来源。这相当于把关系本身变成可带属性的对象，并非宣称发明了新的知识表示理论。

示意：

```text
候选病因 A ← SUPPORTS / WEAKENS / LIMITS — 条款 C
条款 C — REQUIRES → 条件组（AND / OR / NOT）
条款 C — ABOUT → 检查或表现
条款 C — AT_LEVEL → 认知 / 综合征 / 病理病因
条款 C — EVIDENCED_BY → 原文片段 → 文件、页码、版本
条款 C — HAS_EXCEPTION → 例外条款
```

“A 存在某特征而 B 未录入该特征”不是 A/B 差异证据。只有原文明确比较，或审核通过的两侧独立条款形成完整比较包，才建立 `DISTINGUISHES(A,B)` 检索关系；它表示文献层面的鉴别关联，不是自动证明患者属于 A。

### 2.2 核心对象字段

| 对象 | 最少字段 | 作用 |
|---|---|---|
| Source | source_id、标题、发布年份、版本、文件哈希、页码/段落、source_group、来源类型 | 定位、版本及同源归并 |
| Clause | clause_id、原文 span、规范化主张、判断层级、对象、方向、条件表达式、例外、来源 ID、审核状态 | 检索与约束的最小知识单元 |
| Condition | 字段、比较运算、取值、单位、检测方法、时间范围、人群、逻辑组合 | 保留阈值和前提，避免只剩实体关系 |
| Observation | obs_id、主体、字段、原值、标准值、单位、时间、检测方法、极性、状态、原始出处 | 当前病例的事实底座 |
| Need | need_id、候选对、判断层级、需求类型、已知条件、未知条件、重要性、关联结论 | 表明检索到底要补什么 |
| EvidenceBundle | bundle_id、完整条款集合、原文、适用状态、作用模式、来源组、覆盖需求、token 成本 | 作为选择和发送给模型的对象 |
| Claim | claim_id、层级、表述、患者依据 ID、知识依据 ID、未决项、允许强度 | 结论级追踪与约束 |

`source_group` 尽可能追踪共同原始指南、研究或转载链；无法确定独立性的来源标记 unknown。不同文件名、不同 Agent、不同检索轮次均不构成独立来源。

### 2.3 患者观测不是“阳性/阴性”两个值

最少区分 `present`、`absent`、`not_recorded`、`not_measured`、`uncertain`、`conflicting`。例如“未见相关记录”不能写成“明确否认”；“未查”不能写成“检查阴性”；同一字段的相互矛盾记录不能通过最后一条覆盖。

量表、检验必须保留原始单位、参考范围和平台；时间比较必须指定评估时点。工具输出另记录工具版本、适用人群和其本身的限制，不能伪装成医师原始观察。

### 2.4 条件采用三值逻辑，并另保留冲突标志

对每个原子条件，求值为 T（已满足）、F（明确不满足）或 U（未知）。冲突观测不作 T/F 选择，返回 U 并置 `has_conflict=true`。

- AND：有 F 则 F；全部 T 则 T；其余 U。
- OR：有 T 则 T；全部 F 则 F；其余 U。
- NOT：T/F 互换，U 保持 U。

定义条款对病例的适用状态：

```text
A(c, x) = Eval(phi_c, x)
A(c, x) 的取值为 T、F、U 之一。
phi_c 表示条款 c 的条件表达式。
```

注意：**条款前提满足只说明“可以使用这条知识”，并不说明结论已经成立。** 还必须检查患者观测是否满足该主张的事实要求、条款允许的结论方向与强度。

当 `A=U`，可以检索条款解释“缺少哪个条件”；当 `A=F`，可以用它说明“为什么此条款不适用”。这两种用法均不能进入患者病因的正向支持集合。

## 3. 离线准备：建立条件化鉴别证据图

图谱建设是检索算法的前置工作，与在线查询分开进行。首期围绕既定候选病因范围建立小型审核知识库，不追求全病种规模。

| 步骤 | 操作 | 交付及检查 |
|---|---|---|
| 1. 登记原文 | 保存指南/共识版本、文件哈希、页码及来源关系 | 确认可定位且属于实际医学依据；方法论文的示例不能直接变成规则 |
| 2. 切分条款 | 按章节、编号、表格和脚注保留逻辑完整单元 | 前提和例外不被固定长度切块截断 |
| 3. 抽取结构 | 提取对象、方向、层级、条件、例外与对应原文 | 无法可靠解析的条件保留原文并标为待核对 |
| 4. 对齐与审核 | 术语对齐；核对阈值、单位、方向及出处 | 关键可执行条款需审核；LLM 自检不能替代原文核验 |
| 5. 建立鉴别关联 | 显式比较条款，或两侧经审核的可比较条款组成比较包 | 不因图中缺少 B 的边，就认定某表现能排除 B |
| 6. 去重与发布 | 归并同主张同条件的重复，保留不同版本，构建图与文本索引 | 两种索引指向同一条款 ID；评价期间版本冻结 |

图与文本保存同一批知识：文本便于召回原句，图便于沿条款找到条件、例外和比较关系。测试问题不能反向用于补图后再测同一批问题。

## 4. 在线检索算法：从需求到证据集合

本节按实际执行顺序展开：建立需求、召回候选、核对条件、选择集合。

### 4.1 输入、输出与符号

输入为病例观测集合 `x`、判断层级 `l`、候选集合 `H`、证据需求集合 `U`、知识图 `G`、文本索引 `I`、最终证据预算 `B`。输出为证据包集合 `S`、未覆盖需求、适用状态和选择轨迹。

| 符号 | 意义 |
|---|---|
| `h_i,h_j` | 两个候选病因或贡献组，不预设互斥 |
| `u in  U` | 一个鉴别、限制、条件核对或替代解释需求 |
| `d` | 条件和来源完整的候选证据包 |
| `M_du` | 证据包是否按指定用途完整覆盖需求；首期取 0/1 |
| `c(S)` | 最终序列化证据包及其引用/状态元数据的 token 数 |
| `r_d` | 重排相关性分数，不是疾病概率 |
| `w_u` | 预先规定的需求重要性权重 |

### 4.2 步骤 1：建立候选集合，避免检索确认偏差

在首期四个病因范围组内保留全部六个无序候选对。排序可根据已知观测决定先处理哪些需求，但不得因 LLM 初次倾向就永久删除其他候选。

已知诊断只能在允许的任务设置中作为病史背景；盲诊实验必须排除直接泄露目标的字段。图谱候选不包含真实标签。范围外候选独立登记，不强行加入一个缺少审核知识的新诊断分支。

### 4.3 步骤 2：把鉴别任务转换成需求集合

每个候选对从审核的任务模板和知识 schema 实例化需求：

- 差异条款：哪些已观察到的表现，文献认为对两者区分有帮助？
- 适用条件：当前证据的检测平台、人群或时间条件是什么？
- 限制与反向条款：什么条件会削弱当前拟议结论？
- 替代解释与并存：相同观察是否可以由其他候选或共同贡献解释？

需求生成不能读取测试标注答案。允许输出尚未找到条款的需求，也允许“该对缺少足够知识”；不为了填满正反配额而生成不存在的反证。

首期需求重要性采用少量离散等级，例如影响主结论为 2，背景补充为 1；等级由 schema 与结论依赖确定，在开发集冻结。主评价仍使用人工标注的无权重 DEC@B，避免改变权重掩盖未覆盖项。

### 4.4 步骤 3：构造多种查询，不把未知写成阴性

查询由“候选对 + 判断层级 + 已知观察 + 需求类型 + 需核实条件”构成。保留原始病历词语和标准术语两种表达。

例如，查询可以写为“AD 与路易体相关病因的鉴别；已记录认知下降及某项报告发现；检测方法未知，检索该证据的适用条件和限制”。不能把“检测方法未知”补写成某已知平台，也不能把“未记录认知波动”改写成“无认知波动”。

建议每个候选对先发一个综合查询，复核时最多增加三个定向查询；此为起始预算设定，需经开发阶段冻结。所有方法记录实际查询数和返回条目数。

### 4.5 步骤 4：文本和图并行召回

文本侧分别以 BM25 和向量相似度检索原文/条款。图侧将已知实体和候选病因作为种子，使用关系类型白名单检索：

```text
候选病因 → 关联条款 → 原文
候选病因 → 关联条款 → 前提或例外 → 原文
候选对 → 已审核比较关系 → 比较条款包
患者已知表现 → 相关条款 → 候选病因
```

这些路径用于找到知识，不用于直接推导诊断。探索半径可先设为 2–3 条语义边；来源附件与条件闭包单独获取，避免把追踪边也计算进医学推理跳数。每个种子设扩展上限，避免高频节点扩散全图。

图没有候选时退回文本召回并记录 `graph_miss`；文本有结果但未审核的关键规则只可列为待核对，不能偷偷提升为可执行知识。

文本召回采用 RRF 等基础融合：

```text
RRF(d) = sum(1 / (k_0 + rank_j(d)), j in J(d))

sum(..., j in J(d))：对命中的各检索列表求和。
rank_j(d)：证据 d 在第 j 个列表中的名次。
```

其中 `J(d)` 为命中的检索列表，未命中列表贡献 0；`k_0` 是开发阶段固定的常数。不同查询数量带来的票数偏置，通过每个需求先独立融合、再按需求合并来控制。RRF 是基础方法，不是本文创新。

### 4.6 步骤 5：构造条件完整的证据包

对每个召回条款 `c`，沿 `REQUIRES`、`HAS_EXCEPTION`、`EVIDENCED_BY` 取得其必要依赖，形成闭包：

```text
d(c) = {c} union RequiredContext(c) union Provenance(c)

union：集合并集。
RequiredContext(c)：理解条款 c 所必需的条件和上下文。
Provenance(c)：条款 c 的原文出处及版本信息。
```

闭包仅包含解释该条款必需的部分，不能无界扩展。对 AND 条件，所有必要子条件必须出现；对 OR 条件，保留原文的替代关系，不能只保留对当前结论有利的一支。

若 A/B 的比较必须联合两条知识，预先将其打包成一个候选包，并记录双方原文。这样不会出现“两个半条款分别都得零分，贪心永远选不中”的问题。

闭包不完整或过长时，先尝试取得较短但仍完整的原文单元；仍无法满足预算时记为 `incomplete_bundle` 或 `over_budget`，不靠删除关键前提使其入选。摘要可辅助浏览，关键条件仍应由原文支撑。

### 4.7 步骤 6：适用性判定与用途分流

每个证据包携带 `mode`：

| 条件状态 | 允许用途 | 不允许用途 |
|---|---|---|
| T | 在观测和支持方向核对后，作为候选结论依据 | 仅凭适用就确诊 |
| U | 说明条件要求、指出缺口、形成定向复核 | 把未知前提当作满足 |
| F | 解释为什么该规则不适用，限制或撤回误用结论 | 给该患者增加正向病因支持 |

`M_du` 必须按用途计算。例如患者条件未知时，证据可完整覆盖“此检查需要何种平台”这一知识需求，但不能覆盖“该患者已满足诊断条件”这一事实需求。

这里刻意不使用一个软惩罚分数同时承担所有约束：**明确不适用的规则不能因为相关性高就重新进入正向支持。**

### 4.8 步骤 7：计算证据相关性与在线覆盖

建议首期用固定特征重排：

```text
r_d = theta_1 * s_text(d) + theta_2 * s_pair(d)
    + theta_3 * s_level(d) + theta_4 * s_need(d)

theta_i >= 0
sum(theta_i) = 1

* 表示乘法；theta_i 表示第 i 个特征的权重。
```

各特征统一到 `[0,1]`：文本相关性采用冻结的重排器输出或秩归一化；候选对匹配来自审核关联；层级匹配来自节点类型；需求匹配来自条款类型与需求类型。只有满足完整性、审核状态与用途规则的包进入对应的候选集合。

`M_du=1` 要求：候选对和层级相符、条款内容直接回答需求、条件和例外完整、来源可定位、用途被允许。仅有实体重合或向量相似不能判为覆盖。

在线匹配由固定 schema/审核关系执行，语义判断不确定时记为 0 或待核对；离线人工金标准独立标注。必要时允许 LLM 做辅助匹配，但应单独评价其错误，并计入预算，不能用其判断作唯一测试答案。

### 4.9 步骤 8：在 token 预算下优化整个证据集合

定义：

```text
Relevance(S) = sum(r_d, d in S)
Coverage(S)  = sum(w_u * max(M_du, d in S), u in U)
Redundancy(S) = sum(dup(d_i, d_j), 每个无序证据包对只计算一次)

F(S) = eta * Relevance(S) + Coverage(S) - lambda * Redundancy(S)
约束：c(S) <= B

sum：求和；max：取最大值；空集合的覆盖值约定为 0。
eta：相关性项的权重；lambda：冗余惩罚的权重。
```

空集合的覆盖为 0。`dup` 只惩罚同一主张/相同条件的重复及高度重叠内容；同一指南中的不同必要条款不应仅因同源被惩罚。来源是否独立另行记录，不能把“来源多”直接等价于“证据强”。

与 MMR 相比，新增的核心对象是**明确的鉴别需求及其条件完整覆盖**。但这仍是经典预算覆盖思想的任务化设计，不应仅凭公式宣称新优化理论。

采用单位 token 边际收益选择：

```text
S_new = S union {d}
DeltaF(d, S) = F(S_new) - F(S)
DeltaCost(d, S) = c(S_new) - c(S)
rho(d, S) = DeltaF(d, S) / DeltaCost(d, S)

DeltaF：加入证据包 d 后的收益增量。
DeltaCost：加入证据包 d 后的 token 成本增量。
rho：单位新增 token 带来的收益；只在 DeltaCost > 0 时计算。
```

具体过程：

1. 从空集合开始，对完整候选包计算增益与最终序列化增量成本。
2. 只考虑增加后不超预算、增益为正的候选。
3. 选择 `rho` 最大者；同分依次按新增需求覆盖、较低 token、稳定 ID 排序。
4. 更新需求覆盖、重复关系及剩余预算，重新计算边际收益。
5. 无正收益候选、全部剩余包超预算或需求完成时停止，不要求填满上下文。
6. 为缓解贪心局部选择问题，至少与“最佳可行单包”比较；可增加一次可行的一换一局部改进，但是否启用需冻结。
7. 最终按需求组织上下文并重新 token 化；如序列化引入额外开销，删除最小损失的完整包，重新计算覆盖，直到满足预算。

若新包不增加任何序列化内容，则合并其需求映射，不进行除以零的评分；不能凭同样内容获得新的虚假覆盖。添加冗余惩罚、闭包和局部策略后，不宣称此实现具有某个通用近似保证。

### 4.10 一个可手算的选择示例

下面只有抽象条款和教学分数，不对应医学有效性或真实实验。

设预算 700 tokens，三个需求权重均为 1，`eta=0.2`。候选如下，成本已经包含条件和出处：

| 包 | 内容性质 | 成本 | 相关性 | 完整覆盖 |
|---|---|---:|---:|---|
| d1 | 疾病背景介绍 | 200 | 0.95 | 无 |
| d2 | A/B 完整鉴别条款 | 300 | 0.85 | u1 |
| d3 | 当前检查的适用与限制条件 | 250 | 0.80 | u2 |
| d4 | 与 d2 同一原始条款的转述 | 280 | 0.90 | u1 |
| d5 | 另一候选的替代解释条款 | 150 | 0.70 | u3 |

重复归并后 d2/d4 只保留一个完整规范包。初始单位成本增益约为：d1 为 0.00095；d2 为 0.00390；d3 为 0.00464；d5 为 0.00760。依次选择 d5、d3、d2，恰好 700 tokens，覆盖三个需求。

按单条相关性排序则首先取背景和重复材料，容易用完预算却漏掉条件。这个例子仅说明目标函数为何不同，不证明实际数据一定受益。

### 4.11 计算规模与失败出口

设候选完整包数为 `n`、需求数为 `m`、实际选择数为 `s`，缓存覆盖和重复后，朴素逐轮选择约需 `O(sn(m+s))`；这是选择层开销，不含模型推理、索引查询和构图。图遍历在限深限宽下执行，必须记录实际访问边数。

开发起点可设文本每路每查询 top-20、融合后最多 120 个完整包、最终证据 3,000 tokens。若截断候选池，应保留按需求分配的最低候选机会，避免全局高分让某候选对完全消失。上述数字是初始工程设置，不是论文给出的最优参数。

当相关知识不足、实体链接失败或完整包全部超限，输出未覆盖需求及原因，不能改为无来源生成并计为检索成功。

## 5. 与已有算法相比，差异具体在哪里

| 对照工作 | 共同基础 | 本算法拟增加并需要验证的内容 |
|---|---|---|
| Zhao 等人的 MedRAG | 疾病差异知识、图检索和鉴别任务 | 从差异特征转为有原文和条件的完整证据包，显式优化固定预算的需求覆盖。[L1] |
| Medical Graph RAG | 医学图谱及来源追踪 | 在来源关联之外，核对条款前提并区分“可支持患者结论”和“仅解释缺口”的用途。[L2] |

## 6. 如何验证算法有效

### 6.1 主指标

```text
DEC@B(q) = CoveredNeeds(q, B) / TotalGoldNeeds(q)

CoveredNeeds：预算 B 内被完整且正确覆盖的人工金标准需求数。
TotalGoldNeeds：查询 q 的人工金标准需求总数。
```

一次覆盖必须直接回答需求、保留必要条件和例外、来源可定位、用途正确。未知条件可以被解释，但不能被评为已经证实患者满足。无适用需求的查询单列，不自动计满分。

在线覆盖矩阵 `M_du` 与人工评价分开，不能用算法自身打分作为金标准。辅助报告条件误用率、完整条款率、来源重复、候选召回上限，以及每条需求的失败原因。

### 6.2 三组必要对照

| 比较 | 固定条件 | 所检验的贡献 |
|---|---|---|
| 强混合文本 / 普通图 / 本算法 | 同原文、模型和证据预算 | 是否整体改善鉴别检索 |
| Top-k / MMR / 本文集合选择 | 完全相同的完整证据包候选池 | 改善是否来自选择目标 |
| 条件条款平铺 / 条件化图 | 相同人工条款、条件和来源信息 | 改善是否确实来自关系组织，而非更多人工知识 |

优先加入 MedRAG-style 的任务适配，说明其与原实现差别。必要消融为：去候选对查询、去条件判定、以 MMR 替换集合选择、保留字段但去掉图关系。

### 6.3 评价设置

先用 20–30 个开发查询检查流程，再形成约 100 个包含明确候选对、适用条件及限制条款的高质量查询集。按患者或条款组划分开发与留出；权重、规则和图版本冻结后再评测。

可先以 3,000 tokens 为主预算，开发阶段确认后冻结；所有原文、图转写、条件和引用元数据均计费。另报告累计查询/模型调用成本，避免通过大量隐藏探索获得表面上的固定预算优势。

关键留出条款由有相应医学知识的标注者独立判断并仲裁。报告配对结果、分候选对结果和失败案例，不用小样本概念验证声称临床有效。

### 6.4 失败结果应如何解释

若平铺条款达到同样效果，说明主要收益来自条件化知识；若 MMR 已足够，说明集合覆盖目标未体现增量；若金标准条款根本不在候选池，优先改进召回而不是调选择权重。评价应将这些原因分别记录。

## 7. 与算法二的交接

向算法二交付：证据包及原文、每条条款的 T/F/U 与冲突标志、允许用途、已覆盖和未覆盖需求、来源版本、实际 token 消耗。

算法二如发回复核请求，本算法按新的目标需求及约束再次召回，将新旧候选合并去重后重新选择集合。最终证据预算仍为 B，不能把第二轮结果直接追加成双倍上下文。

### 9.3 已有设计与实际运行之间的差距

前文已设计 Need、条件、覆盖矩阵、预算内选择与证据复核。不能把“已有文档设计”算成新贡献，也不能把“存在 schema”当作已经运行该算法。

当前证据支持的缺口是：

1. **任务拆解缺口**：一个问题可需要多个证据要素，现有返回非空即无未覆盖问题的规则不足。
2. **图语义缺口**：共现图可以提供候选线索，但不能承担主张支持、反对或适用性推断。
3. **探索缺口**：现有图查询是关键词匹配，没有根据缺口选择关系类型、回到全局检索或决定下一步动作。
4. **集合选择缺口**：RRF 处理多后端排名，不能单独处理跨需求覆盖、同源重复与矛盾证据保留。
5. **评测缺口**：一份文献和任意命中指标无法充分评估跨文献综合、分歧识别或证据充分性。

### 9.4 三个候选方向

| 候选 | 主要机制 | 实现负担 | 可回答的研究问题 |
|---|---|---|---|
| A：需求覆盖驱动的混合检索 | 拆解需求，BM25/向量召回，预算内证据选择，针对未覆盖需求再检索 | 最低；现有接口复用较多 | 显式证据需求是否比整体问题检索更完整？ |
| B：需求覆盖驱动的图探索 | 在 A 上增加类型约束的单跳扩展、全局重新定位和基于证据状态的停止 | 中等；需可追溯主张图与工具接口 | 图探索是否能找到文本检索遗漏的互补证据，并降低重复探索？ |
| C：查询相关扩散与路径选择 | 查询边权、受预算约束的扩散、证据路径排序，再进行需求覆盖判断 | 较高；需核对数值行为与图规模 | 查询相关传播是否优于固定邻域或普通路径检索？ |

## 10. 建议采用的研究问题与贡献边界

### 10.1 一句话目标

**在不训练模型、检索和上下文预算有限的条件下，根据医学文献问题尚缺的证据，自适应选择文本检索、图谱扩展和上下文补读，并组织保留适用条件、来源与分歧的回答依据。**

建议工作名称：**面向医学文献的条件化证据覆盖与自适应图检索**。先采用第 9.4 节 B 方案。A 是必须超过的强对照；C 不作为第一版依赖。

输入为问题 q、冻结的文献发布版本 R、预算配置 B。输出包含回答、逐项引用、适用范围、文献分歧、未覆盖需求和停止原因。主实验暂以跨文献综合比较为主，事实定位作为简单子集，证据不足作为必测子集。

“无需训练”指不做微调、不训练图神经网络、策略模型或评分器。允许调用固定版本的 LLM、预训练 embedding 与现成 reranker，允许在开发集上选择少量规则参数；必须报告这些选择。建图和标注仍有成本，不能将无需训练写成无需数据或零成本。

### 10.2 需要验证的三个假设

1. **需求驱动探索**：逐需求选择图关系及补检索目标，比固定深度扩展和普通检索循环获得更多必要证据。
2. **条件化证据组织**：在相近人群、方法、比较对象、结局和时间范围内判断主张关系，比仅按语义相关性组织结果更少误判冲突和外推结论。
3. **来源与预算约束**：同源归组、保留成对分歧证据、按最终上下文重算覆盖，可减少重复引用和错误的充分性判断。

三个假设均可被实验否定。若无图的需求检索达到同样效果，应将成果收敛为证据组织算法，不坚持声称图谱带来增益。

**目前可主张的是待验证的机制组合与明确的问题设定。** 更有价值的候选贡献是：把条件可比性、同源依赖和逐项证据缺口共同用于下一步检索及最终证据选择，并证明这些机制分别有效。单纯串联三篇论文、增加多个 agent 或增加字段，不构成充分的算法贡献。

## 11. 数据结构：从术语关联图到可追溯证据图

### 11.1 最小图结构

采用 `Document → Span → Claim` 的来源结构，Claim 关联 Entity 和 Scope。图只组织查找线索，回答依据必须回到原文。

| 对象 | 最小字段 | 约束 |
|---|---|---|
| Document | document_id、标题、版本、日期、doi、source_role、source_family_id | 沿用已有登记；未知来源关系显式标 unknown |
| Span | span_id、原文、页码/定位、上下文 span IDs、release_id | 沿用已有定位；引文必须能在固定版本找到 |
| Claim | claim_id、主张文本、subject/predicate/object、scope、evidence_refs、extraction_status | 主张是某文献的陈述，不自动等同医学事实 |
| Scope | population、method/intervention、comparator、outcome、time、setting | 字段可 unknown 或 not_applicable，不强制所有问题套 PICO |
| Need | need_id、问题要素、required_facets、constraints、depends_on、weight | 分解后冻结原始需求；不许删除难回答要素来提高覆盖率 |
| EvidenceUnit | claim_ids、原文包、scope、source_groups、need_matches、token_cost | 原文包包含必要条件、否定、例外及引用定位 |
| Trace | 动作、输入状态、结果 IDs、预算增量、失败原因、模型/提示版本 | 支持重放和错误归因 |

基础边为文档包含段落、段落支持主张、主张提及实体。`same_topic` 和现有 `associated_with` 仅用于导航；`contradicts`、`supports` 不由实体共现产生。比较主张的关系优先在查询时计算，保存判断依据及版本，避免把一次 LLM 判断写成永久事实。

图可先使用 SQLite 邻接表，不依赖 Neo4j 服务启动。一个“扩展动作”是受类型限制的逻辑一步，例如实体到主张再到来源 span；记录实际经过边数。不得把跨度很大的复合查询伪装成廉价单跳。

### 11.2 建图方式与防止信息泄漏

1. 医学事实语料与算法论文分开。首先登记本地临床指南/共识，再确认是否包含可用的原始研究；当前一篇共识不能承担跨研究实验。
2. 使用固定提示和结构化输出抽取 Claim、Scope 与逐字段 evidence_refs；不存在的信息输出 unknown。抽取器只见文献，不见测试问题、答案或金标准证据。
3. 用确定性代码检查 document/span 存在、引文子串和 offset 一致、否定/例外所需上下文未丢失。检查通过只说明来源可定位，不证明语义正确。
4. 分开保存 `machine_extracted` 与 `human_reviewed`。人工审核小规模开发语料和独立抽样；最终评测的人工金标准不回填测试图。
5. 所有比较方法访问同一份原文和抽取信息。无图方法可检索相同主张与条件的平铺文本，防止把额外知识收益误认为图结构收益。

来源分组按研究身份而非文件数：同一研究的多个报告可同组；指南与所引用研究只有在引用关联被核实时才标依赖。不同 DOI 不必然独立。未知来源关系保留，不自动作为独立重复验证；也不把所有 unknown 强行归为同一真实研究。

## 12. 证据状态、动作与停止规则

### 12.1 问题拆解与覆盖矩阵

LLM 一次生成 Need 集，程序检查每个原问题要素都被保留。比较问题至少包括两个比较对象及比较维度；宽泛问题用明示的默认范围回答，并在输出说明范围。

对 need i 的 facet j 和证据 e，定义二值 `m[i,j,e]`：只有证据直接涉及该要素、引用有效且条件允许该用途时才为 1，否则为 0。相似度和 LLM 自报置信度不能直接替代 m。

对最终证据集合 S，`c[i,j](S)=max_{e∈S} m[i,j,e]`，并定义：

`F(S) = Σ_i w_i × (Σ_j c[i,j](S) / |facets_i|)`，默认 `Σ_i w_i=1`。

独立来源数、比较两侧是否齐全、必要桥接前提和完整条件包另作硬约束，不能被平均分掩盖。常规事实定位允许一个明确来源；题目明确要求跨文献比较时，需覆盖指定文献，或至少两个可区分来源并说明独立性是否核实。不要给所有问题统一加“至少两篇”规则。

每个 Need 的运行状态包括：`missing / partial / covered / disputed / scope_unknown`。`disputed` 不自动等于不能回答：若双方证据及可比条件齐全，可回答“文献存在分歧”；不能在没有依据时选胜方。`covered` 仅指本问题要素在当前上下文中有可用依据，不表示事实被绝对证明。

### 12.2 可比条件与主张关系

按该 Need 的 required scope fields 比较两条主张：

- `comparable`：必要字段一致，或有明确可接受的包含/映射关系及依据。
- `different_scope`：至少一个必要条件明确不同。
- `unknown`：缺少判断可比性所需的信息。

只有 comparable 且针对同一具体命题方向相反时，才标 `candidate_conflict`，并保留两边原文进行核验。different_scope 应组织为条件不同的结果；unknown 应触发补读或限制表述。更晚发表、来源更多、措辞更强都不能自动解决冲突。统计“不显著”不自动转写为“无效”或“反对”。

支持/反对始终相对于待回答的明确命题，而不是相对于疾病实体。缺少证据和存在否定证据是两种状态。

### 12.3 工具接口

| 动作 | 输入 | 返回与约束 |
|---|---|---|
| search_text | need_id、检索式、scope filters、release_id | BM25 与向量候选，经 RRF 合并；保留过滤前后计数 |
| expand_graph | 已存在的 seed IDs、允许边类型、need_id、limit | 有界邻接候选及原文定位；不把路径本身当推理证明 |
| read_context | 已存在的 span IDs、缺失字段 | 相邻段落、章节或表格说明；受长度预算约束 |
| find_contrast | need_id、主张、已知 scope、排除重复的来源组 | 检索相反/限制性表述及其他来源；不得要求一定找到反证 |

LLM 可建议检索式和字段匹配，程序选择合法动作、检查 ID 与预算。工具没有任意 SQL/代码执行能力。检索出的文献内容作为数据，不作为工具指令。图断裂时回退 search_text；图后端失败单列记录，不能伪装成没有医学证据。

### 12.4 可执行的默认调度规则

第一版使用可解释的规则，不训练动作价值模型，也不声称掌握未检索证据的真实收益。

1. 初始以原问题进行一次混合检索，构建候选池和初始状态。
2. 优先处理会改变已有结论用途的缺口：缺失否定/条件上下文 → read_context；疑似冲突且可比性未知 → 补读相应字段。
3. 其次按 `w_i × 未覆盖 facet 比例` 选择 Need；相同则按原问题次序。每个 Need 最多连续占用两个动作，避免一个难点耗尽预算。
4. 已有匹配实体且存在尚未访问的允许边 → expand_graph；否则 search_text。缺少比较另一侧或需要核验分歧时 → find_contrast。
5. 同一 Need 连续两次图扩展无新增可用要素 → 下次改全局检索。只有图拓扑可预知的未访问邻居数可用作候选排序提示，不能当成真实覆盖收益。
6. 同优先级动作按预计成本、再按稳定 ID 排序。预计成本用调用上限或开发集统计；完成后记实际成本。

缓存键至少包含 release、need、动作类型、规范化参数、seed、游标；已执行且输入与数据均未变化的动作不重试。后端失败最多一次受预算约束的重试。Need 状态变化不能成为重复相同查询的借口。

### 12.5 默认预算与停止

以下是开发起点，须经小样本验证后冻结，不是已证明最佳参数：

- 初始检索 1 次，后续动作最多 5 次；每次 BM25/vector 各取前 20，经去重保留最多 20 个候选。
- 每次图动作返回最多 20 个逻辑邻居；每个种子累计最多探索 2 层，整个问题访问最多 100 个不同节点。
- 候选池最多 100 个 EvidenceUnit；溢出时先去精确重复，再保留每个未覆盖 Need 的候选，最后依相关性截断并记日志。
- 最终证据上下文 `B_ctx=6,000 tokens`，计入原文、条件、来源和组织文字。长原文只按语义完整边界拆分，不截掉否定或表头。
- 在线模型调用 token 总上限示例 `B_online=80,000`，输入与输出均计入，预留 20,000 给回答、核验和一次修复。检索循环最多使用 60,000；调用前按输入加最大输出预占，返回后结算。embedding、reranker 和离线建图成本另记。
- 连续两个动作没有新增有效 facet、来源要求满足度、条件字段或已核验分歧信息时视为 stalled；任一维度改善则重置。拒绝以新增无关节点作为进展。

停止原因独立记录：`covered`（必要要素和硬约束均满足）、`budget_exhausted`、`stalled`、`no_legal_action`、`backend_failure`。始终按**装入最终上下文的证据**重算状态。候选池齐全但装不下时不能报告 covered；可继续尝试更紧凑的完整原文包，仍装不下则输出有限回答。

covered 表示已找到足以支持限定回答的材料，不表示穷尽全球文献。若用户问题要求系统综述式全面检索，应另定义检索策略与筛选流程，不能沿用此停止标准声称检索完整。

## 13. 预算内证据组织与端到端算法

### 13.1 证据选择

每个证据包包含主张、必要 scope、原文和定位；依赖的定义/表头作为包的一部分计费。同一研究的重复表述对同一 facet 不增加 F。若问题要求不同来源，将已核实的来源覆盖作为额外的、饱和的 coverage facet；未知独立性不能完成“独立复现”要求。

贪心选择最大 `ΔF / 新增序列化 tokens` 的可行证据包，平局用检索排名、再用稳定 ID。前提互相依赖、单条不能完成要素的证据先合为最小联合包，防止零单项增益导致永远选不到。已发现且相关的可比冲突双方也组成联合包；共享上下文只计一次。联合包无法装入时，不允许只留下其中一方作确定结论；应报告该 Need 无法在当前预算内完整呈现，并保留可核查的分歧摘要和双方定位，摘要本身也计费。只有摘要而缺必要原文时，该 Need 仍不计完整覆盖。

先做贪心，再做有限的 1 换 1 / 1 换 2 局部改进：只接受提高覆盖、或覆盖不变但减少 token 的替换，最多两轮。每次替换重新检查条件依赖和分歧配对闭包。正好填满预算不优先于语义完整性。

固定二值覆盖下，单纯 F 是单调覆盖函数；实际存在依赖闭包、成对分歧、动态判断和预算约束。本方案仅将选择器作为启发式，不引用经典贪心或 QAFD-RAG 的近似保证。固定候选池的小样本可用穷举/整数规划计算覆盖上界，测量启发式的差距。

### 13.2 端到端伪代码

```text
answer_question(q, release, budget):
    reserve final_answer_and_check_budget
    needs = decompose_and_validate(q)           # 原始需求冻结，失败则保留整体问题
    pool, trace, seen = empty
    previous_pool_state = all_missing(needs)
    pending = initial_search(q)
    no_progress = 0
    repeat:
        if not affordable(pending, including_extraction_and_check):
            reason = budget_exhausted; break
        result = execute_validated(pending, release)
        account_actual_cost(result); log(result); cache_action(pending)
        units = validate_quotes_and_extract(result) # 不合格结果保留错误，不能覆盖需求
        pool = bounded_deduplicate_merge(pool, units)
        relations = compare_relevant_scopes(pool, needs)
        selected = select_closed_evidence_packages(pool, relations, B_ctx)
        state = assess(needs, selected)         # 同时检查跨包前提和来源要求
        progress = newly_verified_information(previous_pool_state, pool)
        previous_pool_state = snapshot_verified_information(pool)
        no_progress = 0 if progress else no_progress + 1
        if all_required_facets_and_constraints_met(state):
            reason = covered; break
        if exhausted_action_node_or_token_budget():
            reason = budget_exhausted; break
        if no_progress >= 2:
            reason = stalled; break
        pending = policy(needs, state, pool, seen, remaining_budget)
        if pending is none:
            reason = backend_failure if required_backend_unavailable else no_legal_action
            break
    if no selected exists: selected = empty; state = all_missing(needs)
    draft = generate_bounded_answer(q, selected, state, reason)
    checked = verify_claim_citations_scope_and_coverage(draft, selected)
    if checked fails and reserved_budget permits:
        draft = repair_once(draft, checked)     # 不偷偷增加一轮无上限检索
        checked = verify_again_within_reserve(draft)
    remove_or_qualify_unverified_claims(draft, checked)
    return answer, citations, scope, disputes, gaps, reason, cost, trace
```

`decompose/assess/compare/verify` 所需 LLM 调用全部计入预算。优先批处理新证据和变化的 Need；缓存未变化结果。模型拒绝、格式错误和超时都有确定性 fallback；不能把失败解析成“证据充分”。最终修复失败时删除无法验证的结论，保留已核实部分并注明缺口。

### 13.3 回答格式

按需求组织：结论 → 对应原文引用 → 适用条件 → 差异/限制。最后列出未解决问题与停止原因。引用携带 document/version/page/span；每个实质性断言至少对应一处支持其表述强度的证据。跨文献推断明确标“综合判断”，列出全部必要前提，不能给推断伪造单篇原文出处。

### 13.4 用虚构材料演示决策

以下 A/B/C 和数值均为算法演示，不是医学事实。

问题：“文献对方法 X 在人群 P 中测量结局 O 的表现是否一致，差异来自哪里？”初始召回 A 与其二次解读 A′，两者都说表现较好，来源核实后属于同一组。状态是结论侧已有证据，跨来源比较尚未覆盖。

1. 图扩展共享的 X 与 O，找到 B 的不同结论，但方法字段未知。此时标 scope_unknown，不直接标冲突。
2. read_context 找到 B 使用方法变体 X2。若问题允许比较 X/X2，则记录方法差异；若只问 X，则 B 仅作背景，不完成针对 X 的主张覆盖。
3. find_contrast 在同一人群、方法及结局约束下找到 C，其方向与 A 不同且可比。选择 A+C 联合包，A′不增加覆盖。
4. 若各必要字段和两侧来源齐全，可回答“在所检索文献范围内存在可比条件下的分歧”，不按多数票决定谁正确。

例如三个 facets 为“X 的结果、比较侧结果、差异条件”，三个权重相同：只有 A 时最多覆盖 1/3；A+A′仍为 1/3；完整 A+C 和条件原文可覆盖 3/3。若 C 的条件始终未知，即使有很多相关文章也不能计满。若预算耗尽于第 2 步，输出已知结果、条件差异及尚缺可比研究，停止原因记 budget_exhausted。

改造优先级：先拆出可供文献 QA 复用的多后端适配器，再增加状态层。不要直接把 clinical 的 `uncovered_questions` 改成一个 LLM 布尔值。SQLite provenance 与发布校验机制继续使用；新字段以新表/版本化 schema 增加，旧 95 条关联关系不自动迁移为语义主张。

必要工程测试包括：引用偏移错误、无结果、后端失败、循环重复、scope unknown、同源重复、冲突包超预算、模型格式错误、最终裁剪导致覆盖下降。它们验证会改变答案的边界行为，不能只测试函数存在。最后用小规模真实文献走通，所有新功能通过显式文献 QA 入口启用。

GitHub 参考代码只静态读取后再决定复用，记录地址、抓取日期、commit（可获取时）、文件 SHA256 和许可证。当前三项目是 main 快照加文件哈希，不等于已固定官方发布版。正式复现先锁版本；不要把第三方安装脚本或默认 API 调用直接带入主项目。

## 15. 实验设计与指标

### 15.1 语料、问题与标注

先核对本地临床资料的版本和内容。扩到约 15–30 篇主题相关、可合法获得全文的指南/共识与原始研究作为候选起点；若文献类型和研究独立性不足，不硬凑跨研究任务。规模由覆盖的问题类型决定，不能只以篇数证明充分。

建议先做 20 个开发问题，再独立构建约 80 个测试问题：事实定位、跨文献综合、适用条件差异、可比结论分歧、语料内不足各约 16 个。按实际语料调整并公布分布；没有真实分歧时不能用 LLM 编造医学金标准。困难子集可用明确标为合成的受控材料单独测，不混入主结果。

问题按主题、来源家族和近重复问法分组划分开发/测试。测试问题和答案不参与提示、参数与图修订。固定知识库可包含测试问题需要的文献，这是检索任务的正常设定；另设新文献留出实验时，冻结参数后再自动处理新增文献，并单独报告，不能混称同一种泛化。

每题标注：必需需求与条件、可替代证据组、足够回答的最小证据组合、来源依赖、分歧类型、语料内可回答性和答案要点。两名有相应医学阅读能力的标注者独立标关键部分并仲裁；记录一致性、耗时和未确定项。先看原文建立金标准，再盲评系统答案。LLM 可辅助定位，不作为唯一裁判。

### 15.2 基线与公平控制

| 方法 | 目的 | 要求 |
|---|---|---|
| BM25、向量、混合 RRF | 测基本检索收益 | 同分块、原文与生成器 |
| 混合检索 + MMR | 强单轮证据选择 | 同上下文预算 |
| A：需求驱动文本循环 | 检验图的必要性，最重要对照 | 同拆解、scope、来源字段、停止与预算；只移除图导航 |
| 固定图扩展 | 检验动作自适应 | 同图、候选限额、选择器 |
| ARK 适配版 | 检验工具探索策略 | 说明实体排名到证据 QA 的适配；单 agent 为主，原多 agent 配置另报总成本 |
| PathRAG 适配版 | 检验路径组织 | 说明代码参数、无向化及深度差异，保留医学原始边方向；不得声称严格原版复现 |
| 通用充分性循环 | 排除一般“再检索”收益 | 参考 AdaKG-RAG 思路实现的概念对照；无官方复现证据时不冒称原算法结果 |
| B：完整方案 | 检验联合机制 | 同语料、模型和发布版本 |

QAFD-RAG 可在主实验稳定后加入。先验证数值过程和图转换，不承诺其理论保证成立于当前实现。KnowGuard/PAGE-RAG 先作方法边界对照；若复现成本可控，再增加经过明确适配的实验。

做两种公平比较：①相同最终上下文，报告总在线成本；②相同在线预算上限和调用资源，比较质量。不得只限制最终 6,000 tokens 而隐藏循环探索成本。再在 3,000/6,000/10,000 上下文预算上画质量—成本曲线。各方法共享同一生成提示；方法特有的证据组织允许保留并计入成本。

### 15.3 必要消融

- 去需求分解：使用整体问题，保留其余处理。
- 去图导航：仍可检索同样抽取信息的平铺文本，排除“更多知识”因素。
- 去条件可比性：保留条件字段，但不参与动作和覆盖判定。
- 去来源分组：观察重复文献是否导致虚假的充分性。
- 用 Top-k/MMR 替换集合选择：固定候选池，隔离证据组织收益。
- 固定步数替换自适应停止：在多个预算点测提前停止错误与节省成本。
- 不保留冲突联合包：检验片面回答是否增加。

主结果先报告少量有明确解释的单项消融；条件判定与来源归组可再做 2×2 组合，避免把所有差异笼统归因于一个模块。

### 15.4 指标定义

1. **Hit@K**：至少命中一条相关证据的问题比例。当前旧 recall_at_k 属于此类，保留历史对照时须注明。
2. **证据要求召回率**：每题金标准有 J 个必要证据要求，每项可对应多套可替代 span 组合；当至少一套完整组合被选中时命中该项。`Recall=命中的要求数/J`，分别对候选池与最终上下文计算；不要用任意一段命中代替整题召回。
3. **完全覆盖率**：全部必要要求与条件都满足的问题比例，由人工金标准计算，不使用系统自评的 F 当真值。
4. **引用支持率与无依据断言率**：逐实质性断言检查引用是否支持内容、条件和语气强度；明确分母并同时报告有回答的问题数。
5. **条件/分歧错误率**：分别统计将不同 scope 误判冲突、将未知当适用、遗漏可比冲突、把不显著写成否定。按该类问题和断言分别说明分母。
6. **错误充分率**：系统以 covered 停止的题中，金标准必要证据仍不齐全的比例。同时报告 covered 题占比，防止靠全部拒答美化。
7. **回答质量与拒答**：答案要点完整性、事实准确性、限制说明；对语料可回答/不可回答两类分别报告回答率和恰当拒答率。预算不足与语料本身无答案分开归因。
8. **成本**：检索次数、图访问数、各类模型输入/输出 tokens、延迟、失败率、离线建图与人工审核成本；金额按实际服务费率另算，不硬编码。

主比较预先指定 B 对 A 的完全覆盖率与条件/引用错误，成本作为共同报告轴。按同题成对比较，给出题目组级 bootstrap 95% 区间；样本少或组数不足时说明不稳定，不宣称统计显著。固定可设的随机参数；抽取/LLM 输出仍可能变化，主比较至少重复 3 次并报告分散程度，费用不足则明确重复范围。

### 15.5 失败判据与归因

- B 不优于 A：图导航增量未被支持，优先检查图是否提供额外连接；允许最终采用 A。
- 候选池覆盖低：召回/建图问题；候选池高而最终低：预算选择问题；证据齐全但回答错：生成或核验问题。
- 收益只在人工修正图成立：报告抽取瓶颈，不宣称自动建图有效。
- 收益只因给本方案更多 token：不能归因算法；重做预算匹配。
- 小样本效果不稳定：扩大独立主题/来源测试，不反复在同一测试集调参。

## 16. 方案评审时优先讨论的取舍

**推荐默认：跨文献综合比较为主任务，B 为主算法，A 为强对照，先做小规模可审核证据图。** 这与当前无需训练、已有来源定位、图语义仍浅的条件一致。

如果最终聚焦指南事实定位，可弱化跨来源要求，把完整条款和条件召回作为主指标；如果聚焦研究效果比较，应优先补充原始研究和 study family 元数据，不能仅用几篇指南检验研究结论异质性。文献问答不自动进行效应量合并，也不把检索分数转换成医学证据等级。

下一步最值得做的实现工作是 P0/P1：完成临床文献清单、20 个开发问题及强文本基线，再决定图规模。无需先购买训练算力或同时复现三个大型框架。
